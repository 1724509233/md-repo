## 一、背景：三个实证 + 一个根立场
### 1.1 实证（2026-10-25 事件链）
1. **审计 ≠ 恢复**：`reversible` 是 frontmatter 里的**声明**，不是**机制**——5 个落地 handler 中没有一个逆操作，状态机无 merged→撤销迁移，账本存元数据 + hash 不存内容。授权通过后系统只能审计，无法恢复。
2. **结构校验缺口**：10-24 两条 adopted 提案（`payload: null` / `source_refs: []`）落盘后卡死——写入口只校验信封，不校验动词参数；畸形意图直到执行时才暴露。（执行器侧已修，见 `2026-10-25-adopted-card-visibility-design.md`；本 spec 把校验前移到写入口，见 §五.1。）
3. **反馈环缺接收方**：executor 的裁决（merged / failed + reject_reason）只回显给人，产出它的 agent 读不回。数据建了，消费者没建。
4. **补充实证（本轮代码核对）**：`_merge_link` 现在**写用户源文档**（往 `<!-- related -->` 块追加 `[[target]]`）——「事实区不可写」与现行代码直接矛盾；提案的 `actor` / `run_id` 由 **agent 自报**在 frontmatter 里，越权守卫与回滚分组都建立在可伪造的值上。
### 1.2 根立场（宪法级）
> **用户区（用户原文）对自动化默认字节级零写，例外仅限「人执笔」写路径（定义见 §一.3）；其余一切是派生状态，必须携带与事实的显式有效性关系；每次不可逆操作留下可恢复的凭据；agent 引导思考，不替用户思考。**
〔v2.1 修订 #A1〕原文「字节级零写」与 §二 user-ask / rebase 写路径矛盾，且 D4「不记例外」使该矛盾无法在下层消解。修法：宪法层正式承认例外，并立即给出例外的名字与边界（§一.3），例外不再散落在各处各自表述。
### 1.3 「人执笔」写路径（宪法级新定义）〔v2.1 修订 #A1/#B1〕
> **「人执笔」写路径**：机器执行写调用、但每次写入的有效性由人**逐次、事前、显式确认**的写路径。目前仅两种：**user-ask**（交互 agent 逐次请示）与 **rebase**（人发起的事实改写确认）。
>
> 成立要件四条，缺一即降格为违宪的自动化写：
> 1. **逐次确认**：一次确认 = 一次写入。无预授权、无批量确认、无会话级授权。
> 2. **事前确认**：确认发生在写入之前，不是事后追认。
> 3. **独立快照**：每次写入前强制全文 pre-image（§三.1，区域快照开关对此路径无效）。
> 4. **身份带外**：该路径的合法性由**工具面绑定**判定（进程入口 → 允许路径集合的静态映射，§2.1），不读任何 agent 自报的身份字段。
>
> 法律拟制：**机器为笔，人为作者**——这类写入在宪法上归类为「人的写入」，不是自动化的第三类写者。D4「沙箱边界绝对化」相应精确化为：「**自动化写路径**（无逐次人确认）对用户区绝对化，不记例外；人执笔写路径不是例外，是另一类写入。」
**意外收获**：可逆性与交互性是同一枚硬币的两面——动作加法化、可逆化之后，agent 对「实时回包」的需求同步萎缩。v2 用加法动词消解 ReAct 缺口，不建双工通道（§七.3）。

## 二、分层：用户区 / 机器区一刀切
v0.1 三层（法律 / 本体 / 账本）保持，本体层按**读者 + 可变性**重新划界：
| 区 | 介质 | 可写者 | 内容 |
|---|---|---|---|
| 法律层 | `config.yaml` | 人 | 角色注册表（+ `verbs` 声明）、预算、trigger |
| **用户区** | vault 用户笔记 | **人** + **人执笔写路径**（§一.3：user-ask 确认制 / rebase 人发起确认） | 用户原文。自动化写路径对其字节级零写 |
| **机器区** | `index/` + `.sync/`（物理位置定义见 §二.2） | 唯一执行器 + 提案机制 | entities、summary 双形态、勘误卡、快照库、账本 |
| 账本层 | `.sync/index.db` | 系统 | changelog + **提案记录表** + **relatedness 表** + 快照索引 |

〔v2.1 修订 #A4〕原「提案区」一行删除：D25 之后 v2a 提案无文件载体，一个无写者、无介质的「区」在架构表里诱导未来重新引入文件载体（正是 D25 要杀死的回潮方向）。`suggestions/` 的约束降格为一条**守卫规则**（§2.1 第 2 条），存量文件归入「惰性遗留物」清单（§十一）。
### 2.1 边界纪律（v2.1 修订后五条）
1. **用户区对自动化写路径零写**：工具边界硬编码路径守卫——自动化通道（bgagent、执行器）的写调用目标 ∉ {机器区} 即拒绝；**人执笔写路径**（user-ask / rebase）单独放行，其合法性由工具面绑定判定，全部快照保护。守卫绑定的是**静态映射：进程入口 → 允许目标路径集合**，不读 frontmatter、不读参数中的任何身份字段〔v2.1 修订 #B1：实证 4 的可伪造 actor 教训必须同样适用于直写通道；交互 agent 与 bgagent 必须走不同进程入口，身份在带外建立〕。
2. **`suggestions/` 禁写守卫（v2a，D25）**：`suggestions/` 路径对一切自动化写调用（含人执笔路径之外的一切工具面）硬关闭。v2a 无投影文件——提案 = 账本记录，控制台唯一人面。控制台对提案的一切「编辑」入口指向账本记录而非文件（盲区 1 修法，§三.4）。存量投影文件 = 惰性遗留物：不重投影、不导入、不删除（删除 = 机器动文件，见 §十一.6 同口径）。
3. **provenance 由 handler 盖章**，agent 不可伪造（派生文件 frontmatter 由落地代码写入，不是提案 body 透传）。
4. **介质跟着读者走（判例化）**：同一事实可以有多个介质副本，**事实源介质由读者决定**，副本必须可确定性重建。relatedness 进 DB（机器读 + 控制台）、快照进 `.sync/`（机器读）、提案通道 v2a 零文件副本（人读者 = 控制台，D25——文件副本唯一读者是 Obsidian，读取路径是控制台时副本冗余）。此句用于挡住未来「为了好看把事实源搬回 markdown」的回潮。
5. **主体 × 工具面 × 守卫对照表**〔v2.1 修订 #D1〕（原文「agent」一词在 bgagent / 交互 agent / 主 agent 三义间摇摆，守卫对象不精确，此处钉死）：
| 主体 | 进程入口 | 允许写路径 | 身份建立 | 删除权 |
|---|---|---|---|---|
| bgagent | bgagent runner（长驻进程） | 仅 `propose` 工具 | 带外（runner 盖章） | 无（注册表硬摘） |
| 交互 agent | 交互工具面（user-ask 通道） | 人执笔写路径（逐次确认 + 快照） | 带外（工具面绑定） | user-ask 确认制 |
| 主 agent | 控制台 API 面 | 仅终审四工具（`decide_record()` 单路径） | 带外（API 面） | 无 |
| 执行器 | executor（单写者串行） | 机器区全部 + **人执笔 rebase 落地**（持人确认凭据，§四 rebase 行） | 系统进程 | 无 |
| 人 | Obsidian / Web UI / 控制台 | 用户区自由 + 控制台全部 | — | 有 |
### 2.2 机器区物理位置〔v2.1 修订 #A3〕
`index/` 为 vault 内目录（Obsidian 文件浏览器可见，`EXCLUDED_INDEX_DIRS` 使其不进图谱与搜索）；`.sync/` 为 vault 外系统目录（Obsidian 不可见，含快照库与账本）。因此：
- 「agent 产出不出现在 Obsidian」精确化为：**不进图谱、不进搜索、不进用户笔记文件**；errata 卡等机器区文件的文件浏览器可见性属惰性呈现，不构成散落。
- errata 卡物化后的**人面收敛到控制台**（查看 / 改写 / 删除走控制台 API）；§4.3「人可随时改 / 删」的动作面 = 控制台，非 Obsidian。
**agent 产出可见性**（摩擦决策，§六.4）：agent 工作产物**不进用户笔记、不进图谱、不进搜索**（related 块退役、勘误进机器区、summary 进机器区、机器边不进图谱）；注意路径 = 控制台 + **打包推送**（§六.4 通知纪律）。被动散落 → 主动推送，注意摩擦不换回。

## 三、可逆：工具边界快照（用户反提案，替代 per-verb receipt）
### 3.1 机制：调用粒度快照 + 条件回滚
**每次不可逆工具调用**前（覆盖三条路径：① agent 直写 `write/edit/move/delete`（user-ask 人执笔通道）② 执行器落地合并 ③ rebase 落地），把该调用**触及的全部文件**的全文 pre-image 存入 `.sync/snapshots/<call_id>/`，记录 `call_id`、类型、触及路径清单、每文件 pre/post hash、actor、run_id。
- **回滚 = 恢复 pre-image**，单位 = **一次工具调用**（批量调用覆盖全部触及文件，原子恢复）。
- **原子恢复协议**：先全量校验（当前 hash == 快照 post-hash 逐文件比对）→ 后全量写；单文件原子写；任一失败立即停止，surface 半面状态给人——不静默完成一半。
- **撞车守卫**：任一文件当前 hash ≠ post-hash = 后续写已覆盖，**拒绝盲写**，surface「该位置在 <call> 之后被 <actor> 修改过，回滚 or 重新生成，人拍板」。回滚撞后续写，系统不自己选边。
- **回滚顺序约束（逆序原则）**〔v2.1 修订 #B3〕：单活快照语义下，同一文件被调用 C1→C2 连续写入后，C1 的回滚必然撞车。因此：**同文件的多次调用，回滚仅支持从最新调用起的逆序序列；乱序回滚预期触发撞车守卫并由其拒绝（预期行为，非故障）**。整批回滚（按 run 逆序批量调单调用回滚）依赖且仅依赖逆序成立——v2b 实现整批回滚时必须保持逆序，本条列入不变量 2 测试场景。
- 整批回滚（按 run 逆序批量调单调用回滚）= v2b 便捷入口；v2a 只有单调用回滚（机制本体）。
- **快照库完整性**〔v2.1 修订 #B2〕：威胁模型 = **防误不防恶**（与 D13「不设计」口径一致，在此明写）。快照入库时计算 pre-image 内容 hash 并记录于快照索引；回滚协议第一步增加「快照自身完整性校验」（pre-image hash 与索引不符 → 拒绝恢复并 surface，不盲写损坏内容）。快照库对一切 agent 工具面**无写路径**（写入仅 executor 与快照模块本体）；GC 约束见下。
- **捕捉范围（P1 gate 钉死，D20）**：LLM 通道全部（交互 agent 直写工具 + 执行器 handler 全集）+ 人类通道仅删除（Web UI）；人类自编辑/移动不捕捉（用户自己的动作，Obsidian 版本历史兜底）。扩展触发条件 = 控制台出现自动化驱动的编辑面，或用户提出自编辑 undo（按 api.py 既有模式机械扩展）。MCP stdio 通道是独立长驻进程，其写路径（write_doc/edit_doc）P2 接线同一捕捉模式（R1），finalize 的降职+认领**收敛为单条原子 UPDATE**（共享 autocommit 连接上 `with conn:` 不开事务——P2 gate 实证 no-op；跨进程原子性 = 单语句 + SQLite 单写者）。
- **确定性引用重写不在捕捉范围（D21）**：move 顺带对引用方文档做的 `[[old]]→[[new]]` 链接重写是确定性、可再生的（重跑 reference update 即复现）——捕捉对象 = 被移动文件本体，不可再生面。
**回滚语义分区**：
| 目标 | 回滚手段 | 理由 |
|---|---|---|
| 用户区调用 | 快照恢复（默认开，强制） | 不可再生，pre-image 是唯一凭据 |
| 机器区 · 确定性产出（entities） | **重新生成**（修规则 + 重跑）；快照默认关 | f 可确定性重建，pre-image 价值≈0 |
| 机器区 · LLM 独一产出（summary、报告、勘误卡） | 快照恢复（**强制开**，即使区域关） | 重跑不必然复现，pre-image 是旧内容的唯一存档（槽覆盖时旧 summary 全文即此 pre-image） |

「强制开」的精确边界（D19）：**配置层任何开关不得对 LLM 独一产出关快照；I/O 失败路径 fail-open**（写照常、快照跳过、记日志、degraded 模式）。两者不矛盾：前者是配置约束，后者是物理失败降级。〔v2.1 修订 #C2：v2a 期间 degraded 状态**必须可见**——捕捉失败计数进控制台待确认面板（与回读注入同源），不等到 v2b 的人通知通道；否则 v2a 运行期内「可恢复凭据」可能静默缺失而无人知晓。〕
**保留策略（钉死，盲区 2 修法）**：
- **每文件至多一个活 pre-image**（该文件最近一次写入的 pre-image；新调用覆盖旧快照）——回滚 = 回到上一次调用前，单活快照语义够用；逆序约束见上。
- **删除类快照单列保留**至人确认清理或 N 天（默认 30 天）。
- **GC 只允许删「被更新快照取代」的旧 pre-image，永不删活的那个**——写成测试锚点（§六.2）。全文历史在账本 hash 链 + 版本控制里，不在快照库职能内。
  〔v2.1 修订 #D2：「版本控制」明确定义 = vault 若为 git 仓库则指 git 历史；若非 git 仓库，此句仅为「账本 hash 链」的冗余表述，不构成独立机制承诺。实施前置检查项：确认 vault 的 VCS 状态并回写此处。〕
- **in-flight 行（已捕捉、写未确认的崩溃残留）GC 永不回收**：crash 每写至多留一条，它可能是该文件唯一 pre-image——删除 = 静默销毁恢复凭据（P1 gate B1）；该行保持可回滚（按 call 查批不过滤 live/finalized）。
- 不设保留策略 = 「可回滚」随时间静默失效，「reversible 是声明不是机制」复发，这次轮到保留策略。
### 3.2 删除
- 自动化无删除权：**`delete_doc` 从 bgagent 工具注册表硬摘**（不是配置白名单——配置是卫生，注册表是机制）。
- 交互 agent 删除 = user-ask 确认制（现行，属人执笔写路径）+ 快照兜底（全文进删除类快照）。
- 不做「物理保留 + tag」：unlink + 全文快照，Obsidian 不残留「已删」文件，代码同一条快照路径。
### 3.3 身份 / 来源 / 调用链：三条硬编码守卫
不设计，落守卫：
1. **可信盖章**：`propose` 工具调用时 runner 用 run 上下文覆盖 frontmatter 的 `actor` / `run_id`，agent 自报值不存在（写入口即消灭冒充，不等执行器）。
2. 执行器与回滚分组只信盖章值。
3. **越权拒绝**：提案 `type` ∉ 产出角色的 `verbs` 声明 → 在 `propose` 工具调用时拒（操作化的 reject_reason 返回给 agent）。
4. 〔v2.1 修订 #B1〕**直写通道身份同规**：人执笔写路径（user-ask / rebase 落地）的合法性判定读**工具面绑定**（§2.1 对照表），不读任何自报字段——提案通道与直写通道适用同一「身份带外」原则。
### 3.4 不可逆行为的预算（收敛到两个人入口）
自动化能触达的不可逆面只剩：**① rebase**（人执笔：人确认的 fact 改写，全文快照）；**② 有损压缩的 summary**（人终审 + 槽覆盖 pre-image）。auto 通道全部是「可再生 / 可删行」的机器区写。删除动词对自动化永久不存在（§三.2）。

| `entity_index` | 机器区 `index/entities.md` | upsert `## entity` section；**schema 固定 `{entity, attrs: {字段:值}, source_refs: [用户笔记路径]}`，value 禁散文** | 可再生 + （区域快照默认关） | auto | 否（上游产出） |

| `summary` · 缓存型 | 机器区 `<stem>-summary.md`（一源一槽） | 槽覆盖，旧全文 = 该调用 pre-image | 一键再生成（LLM 重跑）+ pre-image | 终审 | 是（上游） |
| `summary` · 报告型 | 机器区 `<date>_summary_<slug>.md` | 独立文件；**逐断言行强制 source_refs，执行器/校验器缺 refs 拒收**；标题固定 advisory 框架（「分析认为…」） | pre-image（点态不可再生） | 终审 | 是（上游） |
| `errata`（新，替代 correction） | 机器区 `index/errata/<stem>.md` | 加法卡（§四.3 形态）；**原文永不改、不加指针** | 删卡 | 终审 · 单闸门（adopt = 确认） | 否（候选是上游产出） |
| `rebase`（新） | **用户区** | **人执笔落地：人在控制台确认后，由执行器持该次确认凭据执行改写（§一.3 要件 4，凭据与工具面绑定）；逐次确认、独立快照** | 全文快照 | **仅人触发** | 否 |
| `unmerge`（回滚） | 任意 | 按 §三.1 协议应用快照逆 | 自身即逆操作 | **仅人触发** | 否 |
| `reminder` | 无落地（v1 刻缺） | 控制台通知卡 | — | 终审（无 handler，保持） | — |

〔v2.1 修订 #A2〕rebase 落地者钉死：不是执行器单方面写用户区（那将溢出修正案 1），也不是人手改（那 rebase 就不是动词），而是**执行器在人逐次确认凭据下的人执笔写入**，凭据与工具面绑定、逐次生效。修正案 1 措辞相应修订（§九.1）。rebase 全量落地仍在 v3，但法律地位与执行者自本稿起确定。
**退役三件**：
- **correction 退役** → errata。精确替换动词拆为 `errata`（加法式，agent 可提）+ `rebase`（改写式，仅人）。stale/ambiguous 的精确匹配重试环（10-24 卡死事故根源）随精确替换动词一起消失。存量 correction 提案人工处理，不迁移。
- **link 退役** → relatedness。in-note `<!-- related -->` 块停止追加（用户判「不优雅」）；存量块不清洗（无害）。〔v2.1 修订 #D4：补充——控制台提供一次性人工清理入口（v3 候选，低优先级）；清理动作 = 人触发 + 执行器人执笔落地 + 快照，机器不主动。〕agent 发现的相关性 = 检索性事实，进 DB，不进用户文件。
- **archive 退役** → 哨兵降级为**只读报告**（「N 篇 90 天未动，建议归档」）；实际搬动 = 人在 Obsidian 拖，或交互 agent 代劳（user-ask 人执笔）——自动化不搬用户区文件。连带清账：v0.1「归档建议批次」、现行代码 `archive ∈ AUTO_TYPES`、v1 spec「archive 终审」三处并存版本一并废止。
### 4.1 entity 的消费面（结构化 vs 替用户生成记忆的分界）
value 字段化 = 结构化；value 散文且与用户笔记同池竞争排序 = 替用户生成记忆（标尺违背）。因此：
- 召回中 entity 只当「实体 → 用户原文」的**路由/锚**（attrs 是字段，不是叙述）。
- **不变量**：derived 记录（entities、summary、relatedness）在召回排序中**永不排在同源用户文本之前**（§六.6）。
### 4.2 summary 双形态（性质不同，授权不同）
- **缓存型** = 对用户自己文字的可再生有损压缩 = 结构化，但有界风险「用户读摘要替代读原文」。终审（不动）；差异化给**再生性**：stale 自动降级 + 一键再生成，错的成本封顶。
- **报告型** = 跨文档综合根因（10-24 排查文档的正规形态）= **在生成新知识**（用户没写过的因果判断），以**假设**面目出现才合规：(1) advisory 标题框架；(2) 逐断言 refs（执行器结构校验：refs 非空 + 文件存在；**语义性引用-支持度校验 = v2b 候选**，NLI 式比对）；(3) 终审 + 机器区落盘 + provenance；(4) **永不自动并入用户笔记**——人复制进主区 = 记忆化动作（交互 agent 可代劳，user-ask 人执笔）。
### 4.3 errata 的合规形态（机器指出伤口，缝合线由人画）
「你的笔记这里错了，应为 X」= LLM 对**用户事实**的断言，是全部动词里离「替用户思考」最近的。合规形态三层：
1. **只许 surface 矛盾，不许断言对错**。卡形态：
```markdown
## 矛盾
notes/foo.md §2 与 notes/bar.md §1 记载不一致
摘录 A（foo.md §2）：……原文……
摘录 B（bar.md §1）：……原文……
## 候选读法（candidate, by: 校对员）
应为：……（人确认时可改写）
## 理由
……
```
「应为」是**候选值、标注出处**；人确认的是「矛盾属实」，候选是待人署名的草稿。
2. **单闸门**：人 adopt = 确认，卡才物化（物化 = 确权）；reject = 不物化。物化后**系统对该卡只读**，所有权归人（改 / 删走控制台 API，见 §2.2）。
3. **消费 = 并列展示，永不静默替换**：v2b「有效读法」= 召回时原文 + 勘误标注并列呈现；静默替换那一刻机器就在替用户改写他的事实，再可回滚也晚了。
**覆盖保护（D23 语义升格）**〔v2.1 修订 #C1〕：v2a 交付仍按 `<stem>.md` 单槽（频率极低），但**新卡写入前若目标槽已有已物化（adopted）卡 → 执行器拒收并 surface，不覆盖**——D6「物化 = 确权、系统只读」语义自 v2a 起生效，不再等 v2b 的唯一文件名机制；唯一文件名 `<stem>-p<record-id>.md` 仍为 v2b 票。已物化卡被覆盖 = 静默销毁已确权内容，仅存快照且 GC 可回收，v2a 不接受该风险。
### 4.4 relatedness 的分层呈现（发现是引导，呈现方式决定它是不是断言）
- 记录 = DB 一行：`(源, 目标, 依据, generated_at, run_id, ignored)`。一条 = 文档级关系边，**无文本位置、无文本内容、零落地**（不是逐行修订建议）。
- 呈现（介质跟着读者走）：
| 读者 | 介质 | 形态 |
|---|---|---|
| 控制台（主） | 网页 | 文档详情两块并列：「你的链接」（用户 wikilink）/「机器建议」（DB 行渲染，每条带依据摘要 + 忽略按钮） |
| 召回引擎 | 直接读 DB | 相关度信号参与排序，无投影 |
| Obsidian | **默认无** | 可选机器区导出 `index/related-suggestions.md`（`projection: true`，纯渲染） |
- 机器边与用户 wikilink **分列两层**，默认只画用户层；机器边是「建议」层（一键忽略）。
- **忽略 = DB 行写标记**（不是改文件）→ 进遥测。反馈环定性（v2.1 修订 #C3）：**v2a 遥测仅供人分析（软约束，如实承认）**；「忽略过的配对下次少提」若要兑现为硬约束，实现为**生成后机械过滤**（executor 落地前按 ignored 配对集剔除边，确定性行为，可测试）——归 v2b；v2a 不宣称提示词级的「少提」，避免与全文「提示词自律不可审计」的方法论自相矛盾。
- 全系统「建议」分型（定案）：
| 形态 | 粒度 | 模型 | 人的动作 |
|---|---|---|---|
| relatedness | 文档级（无位置、无内容） | 推荐位 / 检索信号 | 浏览 · 忽略 · 自己写链接 |
| errata | span 级（old 摘录 + 候选 new） | 修订 / tracked changes | 确认矛盾 · 改写候选 · rebase 落地 |
| 报告型 summary | 整篇（机器区物化） | advisory 报告 | 读 · 引用 · 复制进主区（= 记忆化） |

## 五、提案：记录进账本 + 创建改工具调用 + 协同终审
### 5.1 数据结构化（D-P1 / D-P2）
- **记录进库**：`index.db` 提案记录表（`id, type, actor, run_id, status, payload(JSON), source_refs, justification, reject_reason, created_at, updated_at, merged_at`）+ 状态变迁历史表。**状态以账本记录为唯一状态源**；状态机从「改文件」变「改记录行 + 记变迁」。**v2a 零文件落**（D25）：无投影文件，记录 + 状态账本即全部；relpath 保留为卡片寻址标识（合成，无文件）。存量 4 条 merged **不导入**（记录从切换日起；无内容 diff 可补，伪造凭据比没有更危险——承 v1 D7 口径）。
- **创建 = 工具调用** `propose(type, payload, source_refs, justification)`：agent 写不了 SQL，提案创建从「写文件」改「调工具」。一步带走三件事：**同步校验**（工具参数即校验点：信封 + per-verb payload schema，畸形**零落盘**、当场报错返回 agent）、**可信盖章**（§三.3.1）、**越权拒绝**（§三.3.3）。`suggestions/` 进禁写守卫（§2.1 第 2 条）；10-22 文件级校验钩子（`validate_suggestions_write`）退役，换工具级。
- **状态机（v2.1 修订 #B6，补全出边）**：
```
awaiting_review ──人 adopt──→ adopted ──executor──→ merged
       │                                              │
       ├──人 reject──→ rejected                       └──人 unmerge──→ （回滚，快照逆）
       ├──14 天 TTL──→ expired
       └──failed（executor 拒收，reject_reason）
expired ──人 revive──→ awaiting_review（变迁记账，仅人可复活，agent 不可；
                        revive 后重新计时 TTL。人休假 15 天回来不必重跑 LLM）
failed  ──agent 重 propose（新记录）──→ awaiting_review（旧记录只读存档）
```
- **待审队列 TTL**：`awaiting_review` 自创建起 14 天未审 → 自动转 `expired`（actor=system，变迁记账）；回读注入的未决计数不再挂僵尸条目。〔v2.1 修订 #D5：14 天为**占位默认值**，实际值由 `config.yaml` 配置；「裁决认下」指机制本身，数值属法律层参数。〕
- 控制台从扫目录改读库。
### 5.2 协同终审（D-P3，主 agent 无缝作为终审协作者）
- 主 agent 四个工具：`list_proposals(status?/type?/actor?)` / `get_proposal(id)` / `adopt_proposal(id, note?)` / `reject_proposal(id, reason)`。与控制台 adopt/reject API **同一条代码路径**（`decide_record()`），行为必然一致。
- **并发纪律**〔v2.1 修订 #B7〕：状态迁移**只经 `decide_record()` 单路径**，实现为条件 UPDATE（`WHERE status = <期望前置态>`），非法前置态返回错误——adopt 与 executor 消费的竞态、双通道同时裁决的竞态，均由单写者 + 条件更新消解；SQLite 单写者保证原子性，条件 UPDATE 保证状态机不被竞态击穿。
- `get_proposal` 返回**审读摘要**（不是原始文件）：动词、校验过的参数、影响描述、风险级、justification。
- **红线（三条，框架级不是提示词）**：
  1. **agent 只做决策支持 + 执行，不做决策**；auto-triage（agent 自动过掉低风险）明确范围外。终审通道存在的理由就是产物不可逆/承载语义，把人的闸门换成 agent 的闸门 = 授权分层静默降级。
  2. **谁在说话不可混淆**（盲区 3 修法）：摘要的 justification 区块**原样引用提案原文并标注「以下由 <角色> 生成」**；摘要新增的风险评估标注「以下由 主agent 生成」。防止人点头的对象从「提案本身」滑移成「agent 的转述」。
  3. **不得批量 adopt**：对话渠道逐条确认，无「全部采纳」快捷路径（批量是滑移的最短路径）；每次对话渠道 adopt 在 changelog 写显式回执 `actor: human, via: 主agent`，立法痕迹上把「人判」钉死。
- **已知残余风险（明示，不沉默）**〔v2.1 修订 #C5〕：红线 2 保证引用完整与署名分离，但 **justification 本身是 agent 自由文本**——「请直接采纳，此提案无风险」类 framing 内容会原样进入人的终审视野；主 agent 的审读摘要（选材、措辞）本身是一次 LLM 编辑，选材即立场。这是协同终审模型的固有残余风险，靠终审者位置的存在（人可要求看原始记录）+ 通知材料携带完整内容（§6.4）缓解，不宣称消除。
- **落地预演（D-P4）推迟 v2b**：用户区零写后「用户文档将发生什么」恒为空，机器区有快照兜底，预演是第二层保险。v2b 范围收窄为「vault 漂移时 surface」（大部分已被 stale 检查覆盖）。v2a 的合并时复算只做结构校验（source_refs 存在性 + hash），漂移 → surface 不盲落。
### 5.3 回读注入（框架级反馈环）
runner 每次 run 在上下文头部注入本角色：**未决 N 条 / 失败 M 条（含 reject_reason）/ stale 派生 K 条（v2b）/ 被忽略的 relatedness 配对（遥测）**。有界（top N + 截断标注）。提示词自律不可审计，框架注入是硬约束——run N 的失败必然在 run N+1 的上下文里。

## 六、人在回路：四个位置 + 摩擦核算
| 位置 | 时机 | 动作 | 变化 |
|---|---|---|---|
| **立法者** | 事前 · 规则级 | 写/改 config.yaml（角色、verbs、预算、trigger）；UI = 编译器 + 校验器，文件唯一事实源 | 不变 |
| **终审者** | 事中 · 产物级 | 只审两类：**summary（双形态）+ errata**。位置不变（人判），**位置搬家**：对话（agent 预消化 + 材料）与控制台双通道 | 终审面从 5 动词收敛到 2；信息加工量从「人读 schema」降为「听摘要」 |
| **抽查者 + 回滚者** | 事后 · 回滚级 | 看流水/投影；不满意 → 单调用回滚（带撞车守卫 + 逆序原则 §三.1）；忽略机器建议 | 新增：可逆产物上，人从事前审批移到事后抽查 + 一键回滚 |
| **书写者**（明示） | 随时 | 人复制报告/勘误进主区 = 记忆化；人写 wikilink = 把机器建议转正；rebase = 人发起（人执笔落地，§四） | 「引导不替想」的落地：agent 产出转正永远是人的书写动作 |

**摩擦净核算（@oracle）**：净下降。省掉：correction 精确匹配重试环（10-24 事故根源）整个消失、link 往笔记插块的侵入感消失、终审面 5→2、误 merge 的恢复从「审计都做不到」变一键 pre-image——削减都发生在用户最痛的点（agent 动我的原文）上。**坑**：产出可见性从「散落在笔记里」收拢成「只剩控制台」= 注意摩擦**集中化**而非消除，主动查的频率随时间衰减。
### 6.4 通知纪律（坑的修法，兑现 v0.1 §8 承诺）
每条进入终审面的提案（summary / errata）+ 每份哨兵 / 叙事者报告 → **推送打包终审材料**（内容 + 来源 + 处理结论 + 相似比对）+ 深链直达控制台该卡。一条一推，克制（防「通知退化成我爱你第一千遍」）。
〔v2.1 修订 #D3〕**量级守卫**：通知有自己的反噬风险——批量 run 可一次产生十条推送，正是本条要防的坑。守卫三条：(1) **日上限**（config，默认 20 条/日，超出折叠为一份摘要推送）；(2) **同类合并**（同一 stem 的 stale summary 重生成、同 run 多条 relatedness，合并单推）；(3) 推送预算与 `budget` 同级进法律层，由人调整。通知噪声 = 注意摩擦的回流，计量进遥测（推送打开率衰减 → 立法者信号）。

|---|---|---|
| 固化者 | entity_index / relatedness / summary 双形态 / **errata（v2a 起配入 verbs）** | trigger 增加 stale 武装条件（v2b）；回读注入含 ignored 遥测 |
| 哨兵 | **无落地动词**（只读报告） | 召回遥测 + 衰减分桶 + 归档候选报告；与叙事者同构（v0.1 §6.3「归档建议批次」退役） |
| 叙事者 | 报告（非提案，只读产出） | 天然可逆，零风险 |

### 7.5 硬约束汇总（框架层强制，非提示词自律）
1. 用户区对**自动化写路径**字节级不可写（路径守卫，§2.1；人执笔写路径另立，§一.3）
2. 写提案 = propose 工具，同步校验 + 盖章 + 越权拒绝（§五.1）
3. bgagent 注册表无 delete、无任何直写工具（§三.2 / §7.2）
4. 每次 run 上下文注入未决/失败/ignored 清单（§五.3）
5. provenance 由 handler 盖章（v2b 接线，机制 v2a 落位）
6. 防自触发 / arm ≠ run / budget / max_proposals_per_run（承 v0.1）
7. 执行器内零 LLM（承 v0.1）
8. 身份带外：一切合法性判定读工具面绑定，不读自报字段（§2.1 / §三.3.4）〔v2.1 新增〕
9. 快照库对 agent 工具面无写路径（§三.1）〔v2.1 新增〕

## 十、不变量（测试锚点，验收标准）
1. **用户区 hash 稳定**：全流程（bgagent run → 提案 → 终审 → 执行器落地）跑完后，用户区文件 hash 不变（测试内排除 user-ask / rebase / 人的动作——这三条是**人执笔或人直接**的合法写路径，且 user-ask / rebase 各自的写入必须携带独立快照与逐次确认凭据，凭据缺失 = 测试失败）。
2. **快照与回滚**：每个不可逆调用（用户区）有活 pre-image；vault 副本上 dry-run 回滚恢复到 pre-state；**GC 永不删活 pre-image**（构造「新调用覆盖旧快照」场景断言）；撞车时拒绝盲写且 surface；**乱序回滚（跳过中间调用）预期触发撞车守卫并拒绝**（构造 C1→C2→回滚 C1 场景断言拒绝、回滚 C2→C1 逆序成功）；快照 pre-image 自身 hash 校验失败时拒绝恢复并 surface。
3. **relatedness 分层**：机器边只存在于账本库与控制台渲染；用户区文件零机器边字节；忽略 = DB 标记且进入固化者回读注入（遥测面）。
4. **写入口校验**：畸形 payload 的 `propose` 调用零落盘且报错返回 agent；越权动词（type ∉ verbs）调用被拒；agent 直写 `suggestions/` 被路径守卫拒绝。
5. **零文件落（v2a，D25）**：提案通道不产生文件——create/advance 无文件写、无 change_log 行，`suggestions/*` 零变化（存量文件惰性）；提案状态只信账本记录（测试锚点 = 全流程后 `suggestions/*` 零变更 + 提案通道零行）。
6. **排序纪律**：derived 记录（entities / summary / relatedness）在召回排序中永不排在同源用户文本之前。（实现注记，P2 gate：机器区本就 FTS 池外——`EXCLUDED_INDEX_DIRS`（v1 机制）——derived 根本不进召回，测试锚点 = 全流程后 `index/*`、`suggestions/*` 零 segment；排序侧降权护栏 v2b 接线后生效。legacy 用户区 v1 summary → D22。）
7. **生成类动词合规**：报告型 summary 逐断言 refs（缺 refs 的提案在 propose 调用即拒）；errata 候选标注 `candidate, by: <角色>`；确认后召回中原文与勘误**并列**（v2b 接线，v2a 断言卡内容与标注）；**已物化卡不可被新卡覆盖（断言执行器拒收行为，§4.3 覆盖保护）**。
8. **回读注入**：构造 run N 失败（reject_reason 非空），断言 run N+1 上下文包含该失败与理由。
9. **终审红线**：对话渠道 adopt 在 changelog 记录 `actor: human, via: 主agent`；不存在任何批量 adopt 代码路径（静态断言）。
10. **LLM 独一产出强制 pre-image**：机器区快照默认关配置下，summary 槽覆盖 / 报告 / 勘误卡落地仍产生 pre-image（旧全文可读回）；配置层面不存在任何能对该类产出关快照的开关（静态断言）。
11. **状态机竞态安全（v2.1 新增，#B7）**：并发 adopt/reject 与 executor 消费的交叉场景下，条件 UPDATE 保证每次迁移满足前置态，非法迁移返回错误且零副作用（构造双通道同时 adopt 同一提案场景断言恰一条成功）。
12. **expired 复活权限（v2.1 新增，#B6）**：expired → awaiting_review 仅人可触发；agent 工具面无 revive 入口（静态断言）。

## 十一、范围外（明示不做）
1. **agent 自主撤销 / 自主 rebase / 批量 adopt**：人独占（§五.2 红线）。
2. **auto-triage**（agent 代终审）：范围外（§五.2 红线 1）。
3. **同步 ReAct 回包**：v2 不建（§七.3）；加法动词消解了主要需求，迭代角色出现时再立项。
4. **多文件事务 / 目录改名 / 删除**：执行器保持单文件粒度；自动化无删除权（§三.2）。
5. **事实 vs 事实矛盾的自动裁决**：只 surfacing，裁决是人（v3 检测，裁决永远人）。
6. **存量合并的回滚**：快照与提案记录从切换日起；存量 4 条 merged 不回滚、不补凭据、不导入。
7. **前端法条编辑**：承 v0.1 控制台三期排期，不与本 spec 耦合。
8. **用户区 ghost text / 行级修订建议**：机器不提议对文本的编辑——全系统唯一的 span 级建议是 errata（§4.4 分型表）。
9. **记忆化副本的自动追踪**（v2.1 新增，#C4 关联）：人复制报告/summary 进主区后，主区副本与机器区原件各自演化——原件 stale 再生成，副本无 stale 机制。v2a/b 不做自动追踪（自动追踪 = 机器伸手进用户区，违宪）；该漂移由人自理，「引用而非复制」的机制属 v3 候选。此处明示，防未来把它当 bug 修。
