· 删除分流

…删文档分两条路走：您亲手删的，先进回收站，静静留着等一声招呼；机器自己腾挪的，不进回收站，只在改动前留一份底。两条路都在删除那一刻记下内容指纹——日后真要找回，才知道落回去的那份和您删掉的是不是同一个。回收站不是保险箱，它只管您这一侧的删除…

· 清理与保留

…回收站不会自己长大，也不会自己悄悄过期。清一次回收站，顺带修掉那些指向已删文档的引用——链接文字还在，只是不再跳向空处。清理不碰冲突副本：那是两边内容都留了底的东西，宁可多占一页纸，也不替您做主。若同一篇文档在回收站里躺得久了，它会在待办里问您一句：留，还是走。留，它继续安静待着；走，才是真的删除——真删除之前还是会再留一份最后的底，只是这份底也不久留，够反悔一次就算尽了心。清理之后，目录里的引用计数跟着回落，关联列表里那些灰掉的小点也就少了——这一切都不动您文档里的一个字，也不动别人文档里指向您的那一行。…

· 找回

…从回收站里找回时按原路径落回；原路径若已被别的文档占了，就在旁边落一个副本，并告诉您它去了哪儿。找回之后，它就又是一篇普通的文档，翻篇。…

回收站与恢复

删掉的文档不会凭空消失。这篇文档讲清三件事：删除时分了哪两条路、回收站怎么清、以及找回时它会落回哪里。

删除分流

删文档分两条路走：您亲手删的，先进回收站；机器自己腾挪的，不进回收站，只在改动前留一份底。两条路都在删除那一刻记下内容指纹，日后对账用的就是它。

找回时按原路径落回；原路径若被占了，就在旁边落一份冲突副本（如 回收站与恢复.conflict-mac.md），绝不覆盖。

  • 三 token 共读：--col-measure: 680px（= 文档列现值）· --col-topline: 16px · --col-inline: 24px——doc 与 search 两视图逐像素同值，「同几何不同实例」（各自滚动容器）。
  • mark 分层（§11 豁免规则）：每张片段卡内首处命中 = brass 12% tint 底 + 主墨；同卡后续命中 = 600 字重、无底色。黄铜底块数 O(命中数) → O(卡片数)（本屏 5 卡 = 5 块底）。
  • active 态（键盘选中）：brass 8% 底 + 左缘 2px 黄铜条——刻意复用 rail 三态选中语法，不教第二套选中语言。相关性条已退役（本屏无黄铜细条）。
  • dock 与列心：dock 系 fixed 出流，宽度不参与正文居中；摘除旧 padding-right 非对称让位后两视图对称居中，列心 = 视口心（本稿按修法定制，dock 幽灵位仅供对照）。
  • 加载态两分支：有旧结果走压暗——按剩余亮度 60%（opacity .6）绘制在结果列表整体上；若原意指不透明度 40%，目检时把压暗值一键改成 .4 即可。reduced-motion 下无压暗过渡。
  • 骨架屏仅无旧结果分支：首次搜索 / 上一次是零结果 / 已重置时结果列表无可压暗，meta 行「检索中…」照旧，正文列铺骨架——灰条色为 --ink-soft 16% 低透明度档，组间距 24 / 组内 10 与真实结果态同刻度（结果替换不跳版）；shimmer 为纸色扫光，@media (prefers-reduced-motion: reduce) 下停动效退静态灰条。
  • 搜索态 chrome：dock 整条不渲染；FAB 本体 40% 透明但恒可点/可 Tab（Esc 链后备出口），右上聚合徽标恒全亮；握把按「无 dock → 纵向居中」既有规则归位；不新增任何 z-index 层。
  • 档位 chip：当前档标签取响应档位——零命中时服务端同请求内已自动放宽到 fuzzy，故零结果态文案不再给「放宽按钮」（无档可放）。对用户呈现名＝精确（strict）／邻近（near）／宽松（relaxed）／模糊（fuzzy）。
  • 文案口径：页内框「搜索全部文档内容」（树内框「按文件名筛选」，分工钉）；隐私提示为条件式措辞、零计数零路径。
