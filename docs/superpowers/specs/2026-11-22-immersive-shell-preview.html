同步通道设计说明

同步的每一次往返都走同一条通道：客户端上报本地清单，服务器按三方对比分类，再分别处理上传、下载与冲突。分类的基准不是「上次扫描」，而是上次双方确认一致的哈希。

基准选错，冲突就永远迟到一拍——这也是我们把「已确认哈希」单独记档的原因。

三方择级

  • 本地与基准一致、服务器有更新 → 下载
  • 本地已改、服务器未动 → 上传
  • 两边都改 → 落冲突副本，两版都留着

择级顺序是承重的：非一致守卫必须先于「本地未动」判定评估，颠倒顺序会让冲突从入口复活。

pythonsync.py
def classify(path, base, remote, local):
    if base is None or local != base:
        return "conflict" if remote != base else "push"
    if remote != base:
        return "pull"          # 服务器有新版本
    return "noop"
