## 0. TL;DR

**搜索不是浮层，是一页。** 桌面端从「FAB 扇弧 → 380px 左抽屉」改为「`#search` → 主区单页」：与文档列同宽、同顶线、同几何（**各自滚动容器**，视觉同一容器由三 token 保证，见 §3），点结果 = 列表淡出/文档淡入**原地变身**（眼睛不横向跳跃——这是本稿唯一的目的性收益，其余为附带）。

三件连带事一并做：① **撤销 260px 窄栏的全部呈现妥协**（按文件分组、放宽命中窗口、内联级渲染、退役相关性条）；② **检索策略配置分三层落位**（查询档＝页内内联 / 设备偏好＝localStorage / 全局默认＝config.yaml `search:` 段 + 设置页第 4 分段），**档位绝不进设置浮层**；③ **树内 RAG 下拉退役（桌面条件化）**，FileTree 搜索框复位为纯文件名筛选（消灭"同一动作多入口"）。

黄铜预算在本稿有一处**必要豁免 + 一条新规则**（首处命中上底、后续命中只加粗）——搜索页天然是全库彩色最密的一屏，不豁免就得失控。

## 1. 背景与目标

**现状**（immersive-shell W1 实装后）：搜索 = FAB 扇弧子钮 → 380px 左浮层抽屉（§4 表第 2 行），组件为 `SearchPanel.js`（10-18 起为 260px 边栏页，W1 换壳进抽屉，卡片模板未随宽度重做）。

**痛点**：
1. **形态与使用序列错配**——抽屉暗示"边读边看结果"，实际使用是"搜→点开→撤"，一波用完就走；抽屉在"读"的旁边长期占位却从不被共存使用。
2. **信息量与宽度长期对冲**——10-18 的定调原话是「解决搜索框展示信息不足」，结果面板宽度还从 300px 收到 260px（换"切换不跳宽"）。于是 `content` 三行 clamp、首命中窗口化前 30/后 200、heading 降级 pill、相关性条承担全部强弱比较——**四条全是为窄栏打的补丁**，而 `content` 后端一直就返回（后端零改动红利至今没吃到）。
3. **双入口漂移**——树内 RAG 下拉（10-09 立，当时无搜索页）+ 搜索页/抽屉并存，正是 immersive-shell §1 痛点②「同一动作多入口互相漂移」的现存实例。

**目标**：搜索占满主区、零浮层、零新 z-index 层；结果列宽度 = 文档列宽度，跳转零横向位移；策略配置出现在"用户正在想这件事"的地方。

## 2. 建议决策（D1–D7，待用户拍板）

| # | 决策点 | 建议 | 弃用备选 |
|---|---|---|---|
| **D1** | 搜索与首页融合还是独立 | **独立成页**。理由硬约束：首页 spec 契约「Home 组件对壳零依赖，契约只有『占据主区』一条」——把搜索框做进首页即作废该契约。技术论据（评审补）：Home 自带 `hb-scroll` 滚动层与 `v-if="!currentPath"` 门，嵌框即双滚动层 + view 旗标渗入 Home 模板，契约碎得比契约论据更彻底 | 首页内嵌搜索框（Google 式）：否决——首页是"系统向用户汇报"（被动），搜索是"用户找特定一篇"（主动），时序上先读便签再搜；只留大框会摧毁首页存在理由 |
| **D2** | 首页放不放搜索入口 | **不放**。FAB 扇弧已有搜索子钮；首页再加 = 多入口漂移复发。补偿 = `Ctrl+K` 直达（§8，isDesktop 门控，一行 handler，不是命令面板） | 首页放框（两入口，违 §1 痛点②） |
| **D3** | **三页共享骨架做到几页**（二选一） | **v1 只做文档 ⇄ 搜索两页对齐**（同 `max-width`／同顶线距顶／同字号），Home 不强求 | 三页全对齐：需 Home 侧改版式 = **实质触碰"Home 零改动"契约**（720px 自有宽度 + 自有滚动层），须由 Home 会话执行；本稿不越界，进 §16 演进位 |
| **D4** | 状态建模 | **`view: 'home' \| 'doc' \| 'search'` 与 `drawer` 分列**；搜索移出 `drawer` 值域（现值域 `file/trash/null`；**monitor 从未并入 drawer**——T3 批准偏离在案，本稿不重开，见 §9） | 塞进 `drawer`：否决——抽屉是"浮在纸上"，搜索页是"纸现在是什么"；混用则 §4 规则①「openDoc 关搜索抽屉」语义走形 |
| **D5** | hash | **要 `#search`**。抽屉不需深链，全屏页需要（刷新仍在=页面语义）；FAB 中心回首页手法随迁（清 hash）。实施形态须带 §9「三补」（replaceState / 移动 boot 清零 / 跨断点清零），**三缺一退回无 hash 方案** | 无 hash（纯内存，同 10-18 `activePanel` 口径）：与"页"的语义不匹配 |
| **D6** | **树内 RAG 下拉去留**（二选一） | **退役下拉（桌面条件化），FileTree 框复位为纯文件名筛选**（客户端、无请求）。10-09 那次替换发生在搜索页存在之前，前提已变。**形态修正（评审阻塞级）**：下拉今天移动也可见（无断点守卫），退役接线挂 isDesktop 门，移动维持现状；**移动一并退役需用户显式豁免**（见 §7） | (a) 原样保留：两入口漂移；(b) 连框一起删：牺牲"按名快筛"这一真实不同需求（不同动作：名筛选 vs 全文检索） |
| **D7** | 隐私过滤可见性 | **v1 只显"若相关文档在隐私设置中，已被排除"（条件式措辞），不带计数**；计数进 §16 演进位（理由见 §6：计数 = LAN 存在性探针） | 直接显计数：对主人更有用，但在 web 面无鉴权模型下构成秘密文档的存在性预言机——不采 |

## 3. 壳内定位：主区归属与骨架

```
┌────────────────────────────────────────────────┬────┐
│  [顶线槽 = 三页各自的内容，同字号同距顶]         │dock│
│   doc:    面包屑 · 隐私徽标 · dirty 点           │    │
│   search: 输入框（占满 measure 宽）+ meta 行      │ ⇄  │
│ ─────────────────────────────────────────────  │    │
│   正文列（max-width: var(--col-measure)，居中）   │    │
│   doc:    文档信笺                              │    │
│   search: 结果分组列表                          │    │
└────────────────────────────────────────────────┴────┘
 ◉ FAB（search 态降至 40% 透明，仍可点/可 Tab，聚合徽标保持全亮）
```

- **主区归属规则与优先级**（首页 spec §6.1「主区无当前文档且非监控页 → Home」的增项）：显示优先级 **`monitoring` > `view==='search'` > doc > Home**。搜索是显式动作触发的临时态，压过默认态，但**压不过监控页**（监控是独立运行态视图，评审补——初稿只写了压过 Home）。旗标**允许共存**（与今日 `drawer + monitoring` 共存同构），共存时按上述优先级择显。门控清单（五处加 `view` 条件）：`treePinned` 计算、`onFabPick` 的 monitor 支、Home `v-if`、doc 列 `v-show`、bubble-peek 的 `has-dock` 门（见下条）。Esc 折算层同步：`drawer || monitoring || view` 折叠优先级 = monitoring > view > drawer（§8）。
- **同几何不同实例**（评审改写，初稿「三页同一滚动容器」与 §4「滚动位置保留」**物理互斥**——共享一个 scroller 则 doc/search 共用同一 `scrollTop`，两态各自保位不可能）：搜索页**自建 scroller**，padding / topline / measure 全走三 token，视觉"同一容器"由 token 保证。壳高 `html,body,#app{height:100%}` 链不破，回归钉 `test_shell_uses_layout_viewport_height` 照绿。
- **共享骨架的变量**：新增 `--col-measure`（正文列上限宽，**定值 680px** = EditorPane 列现值 `max-w-[680px]`，两值相等由实施期一次确认；Home 720px **出生即豁免**，§16 挂账）、`--col-topline`（顶线距顶）、`--col-inline`（左右内缩）三枚 token，doc 与 search 两视图共读。收益：`Ctrl+K` 与 Esc 的进出 = 同宽度同位置的内容替换。
- **⚠️ dock 宽度必须不参与正文居中计算**（承重，否则本稿核心收益当场作废。评审按真实机制重写——初稿"若 dock 是 in-flow 40px 列 → 改 absolute"是反事实前提：dock **早已 `position: fixed; right: 0` 出流**）：真凶是 `.doc-scroll, .doc-head { padding-right: calc(24px + var(--dock-w)); }`（style.css:2205）的非对称让位——**doc 态列心比视口心左偏 20px** =（64−24）/2，doc⇄search 换列瞬间列心平移 20px，这才是"原地变身横跳"的病根。**修法：摘除这块非对称 padding-right，doc 与 search 两视图同以对称 padding 居中**（EditorPane 列本就 680px 封顶，1024px 视口下列右缘距 dock 左缘尚有 ~132px 间隙——代码层面摘 padding 安全）。连带简化：680 档在 ≥1024 下 dock 与正文根本不可能重叠，初稿「1024–1280 避让」基本是空条款，降为 S1 目检定档项；实施时机 = immersive-shell 合入时顺手做（同一块代码，不开双车道）。
- **搜索态的 chrome**：RightDock **整条隐藏**（无文档语境）；FAB 降透明；文档头行换成输入框（同一顶线槽）。搜索态视觉元素总数应为全壳最低。**连带门（评审独立发现）**：`<bubble-peek :class="{'has-dock': hasDoc}">` 按 hasDoc 让位 dock 槽——搜索态 dock 隐藏但 currentPath 若在，握把/浮窗会空让 40px，`has-dock` 门须加 `state.view !== 'search'` 条件。**同一门律的镜像适用**：左缘文件握把（[[1-项目/md-repo/specs/2026-11-23-file-edge-handle-design]] §3.1/§7）在搜索态**必须保留且全亮**——它是导航入口、不依赖文档存在，故**不得**挂 `hasDoc` 类门；与 FAB「仅降透明不 `visibility:hidden`」同一理由。另：本稿「摘除非对称 padding-right 以统一列心」的动作，与该文 §7「握把不得让正文 `padding-left` 让位」须**同一波执行**（同一块 style.css），否则列心一致的修复会以镜像方式被重新破坏。

## 4. 结果呈现规格（对 10-18 §3.3 的逐条撤销）

分组模型从 **segment 平铺** 改为 **按文件分组、组内片段**——文件才是阅读心智单位，segment 只是定位符。

| 10-18 窄栏规格 | 本稿（`--col-measure` = 680px 档） | 依据 |
|---|---|---|
| 平铺不分组，同文件出多卡、文件名片重复 | **文件头一行**：文件名（`--ink` 14px，500 字重）+ 目录段（`--ink-soft` mono 11px，可给全不截断）+ 组内片段数（弱色小字） | 宽栏下组头仅占一行，窄栏下占比不可接受——约束已解除 |
| 卡片带边框 | **零边框**，纯间距分组（组间 24px / 组内片段间 10px） | 10-07 已定「用间距、字号、字重建立层级，减少边框和阴影」 |
| 首命中窗口化：前 30 + 后 200 字符 | **首命中 ±150 字符**，两端 `…` | 窗口化是为"3 行 clamp 内看得见命中"；宽栏一行容纳字数 ×2–3 |
| `content` 纯文本 | **单趟正则内联级渲染**：`**粗体**`、`` `code` ``、`#` 行首标记剥离（可钉管线见 §17） | 10-18 已为此预留路径；**仍禁止引入 marked**——"半截块结构破坏高度模型"的否决理由今天依然成立 |
| 3 行 clamp | **5 行 clamp + 「展开全文」**（就地展开，`content` 是 segment 全文，**零请求**） | 宽栏 5 行 ≈ 旧 3 行的 4 倍信息量 |
| heading 做 pill chip | **降为弱色文本行**（`--ink-soft` 12px mono，`·` 前缀） | pill 是窄栏的视觉锚点补偿；黄铜预算让给 mark 与 active 态（§11） |
| **3px 黄铜相关性条**（宽 ∝ score） | **退役** | 它是窄栏下唯一的强弱线索所以当时必须留；宽栏下一条横跨 measure 的细条与正文同宽，比较性读不出来。`score` 继续用于排序，**永不显示数字**（非归一化原始值，可能是 17 也可能是 42） |
| meta：「N 个片段 · 当前档 strict」 | **「N 篇 · M 个片段 · 档 [宽松 ⌄]」**——档位做成可点 chip（§5），**对用户呈现名=精确/邻近/宽松/模糊**（映射见下文案纪律）；当前档标签**取响应 `recall` 字段**（零命中时已是 fuzzy——服务端同请求内自动回退，§5 F1 对齐注），初稿示例写 strict 误导默认档 | 当年砍文案的原因是 260px 下换行；约束已解除 |

- **active 态（键盘选中）**：`brass` 8% 底 + 左缘 2px `brass` 条。刻意复用 rail/W1 子钮 active 语法（§3.1 三态），不让用户学第二套选中语言。
- **加载态**：meta 行改「检索中…」；**有旧结果**时旧结果压暗 40% 保留（不清空、不闪跳）；新请求 abort 旧（既有）。reduced-motion 下不做压暗过渡。**无旧结果（首次搜索 / 上次零结果 / 已重置）时出骨架屏，不留空白压暗（2026-11-23 用户追加拍板）**：骨架几何与分组模型对应——约 2 组 ×（1 行组头灰条 + 2–3 行摘要灰条，行宽参差），组间 24px / 组内 10px 与真实结果同刻度（结果替换进来不跳版）；灰条用 `--ink-soft` 低透明度档；shimmer 可有，reduced-motion 下退静态灰条。
- **空态（未输入）**：输入框 + 最近搜索 ≤3 条 chip（可点回填，`mdvault.recentSearches`，只存词不存结果）。**明确不放**：最近文档、待审事项、智能建议——那是首页管家日报的职责，两处都做 = 造第二个首页。
- **零结果态**：「无匹配——若相关文档在隐私设置中，已被排除」（隐私过滤提示并入此句，§6）+ 第二行帮助文案说人话：「已经尽量放宽着找过，还是没有——换个说法，或只留一两个关键词再试。」**档位名（strict/near/relaxed/fuzzy）一律不进说明性文案**（2026-11-23 用户纠正：初稿「已按 relaxed 档找过……fuzzy 档」把设计概念词写进了 UI，违 AGENTS UI 规则 2）。初稿的「放宽按钮（strict→near→relaxed→fuzzy）」撤销（评审阻塞级：现行法源下零结果即 fuzzy 已同请求内自动回退耗尽的**终态**，无档可放，见 §5 F1 对齐注）。若坚持保留：**仅当用户手动把档位 chip 收窄到 strict/near 后**才出现「升一档」按钮——一次点击 = 一个新请求 = 一行落账，不违 F1。
- **文案纪律（AGENTS UI 规则 2 的检索页实例，2026-11-23 用户定稿）**：**档位对用户的呈现名 = 精确 / 邻近 / 宽松 / 模糊**（chip 短标签；下拉项与 tooltip 用全称「精确匹配/邻近匹配/宽松匹配/模糊匹配」，其中邻近/宽松/模糊沿用 10-15 §6 既有文案，精确对补齐）；**内部名 strict/near/relaxed/fuzzy 在 UI 上一律不出现**，只存在于代码与文档；一切说明性文案（零结果帮助、加载提示、空态引导）说人话，不出现档位名/内部概念词。
- **状态保持**：组件 `v-show` 常驻（10-18 §3.4 先例）——搜索词、结果、滚动位置在离开/返回间保留。滚动保位靠**独立 scroller + v-show 常驻**（不是共享容器，§3 同几何不同实例）。
- **点击落账**：rank 维持 segment 级 `record_rank`，keywords 用控制器 `lastKeywords()`（分组模型下"一次点击 = 一行"不变式不变）。顺手修一个既有小毛病：`renderSnippet` 现把原始输入（含 `#tag` token）当命中词打进 `<mark>`——改传 `lastKeywords()` 产出词。

## 5. 检索策略配置：三层，绝不塞一处

**检索流对齐（评审阻塞级新增；法源 [[1-项目/md-repo/specs/2026-11-13-recall-data-chain]] §3 F1，`utils/search.js` 头注逐字）**：现行检索流 = **默认 `relaxed` 单请求 + 零命中时服务端同请求内已自动回退 `fuzzy`**（响应 `recall` 字段即产出档位）；10-18 的分层预取状态机（strict→near→relaxed→fuzzy 多请求）已被 11-13 取代，本稿初稿误按旧流起草。三条硬约束：① **默认档 = relaxed**，档位 chip 只做收窄（strict/near）或升档，不演阶梯；② 每次手动换档 = 新请求 = 新一行落账（F1 允许此形态——写入实施注记，防误加"同查询合行"去重）；③ **不引入 `tier_on_no_result` 式自动补档开关**——多请求阶梯直接推翻「一次意图 ≤2 行落账」不变式并污染 recall 台账。

| 层 | 内容 | 落点 | 存储 |
|---|---|---|---|
| **本次查询** | 档位（默认 relaxed，可手动收窄 strict/near 或升档）、是否含代码块 | **页内内联**＝meta 行档位 chip | 内存 |
| **设备偏好** | 上次选的档、`exclude_code` 临时翻转 | 页内内联，静默记忆 | `localStorage`（同 `mdvault.shellSlots` 套路） |
| **全局默认** | `top_k_default` / `top_k_max` / `exclude_code` | **config.yaml 新增 `search:` 段** + 设置页第 4 分段「检索」 | config.yaml（唯一真相不变） |

**档位绝不进设置浮层（三条独立理由，任一成立即否决）**：
1. **跳数**：搜索页 → FAB → 设置子钮 → 浮窗 → 检索分段 = 五层，且搜索页被压在浮窗下。
2. **成本错配**：写 config.yaml 即继承 revision 守卫 + 422 校验 + 备份 + `os.replace` + **`agent_cache` 代际失效**整条链（settings §4.2/§5.1）。为了"这次想搜宽松点"去 bump 全库配置代际 = 拿重炮打苍蝇。
3. **时序别扭**：热生效是"下一次派发"，页内调完立刻搜可能读到旧默认——用户会以为开关坏了。

顺带红利：meta 行本来就是策略配置的天然落点，配置从"另一个页面"缩成"结果上方一行字"。

**`search:` 段字段（克制版，附默认值；评审后 4 字段 → 3 字段）**：

```yaml
search:
  top_k_default: 12      # 原 8 是为 260px 卡高定的；宽栏按组计，12 片段仍只占 ~1.5 屏
  top_k_max: 50          # 页内「加载更多」上限（防全库拉取）；越界语义见 §14
  exclude_code: true     # R7 的产物（实测 mcp：全列 110 vs 排除 code 99）
```

- **exclude_code 内核现成（评审核实）**：`rag_search` 已有 `include_code: bool = False` 参数 + FTS 层过滤器——**config 默认 `true` 就是对现状的显式化**，零行为变化；页内翻转只差 `POST /api/ai/search` 路由（`routes/recall.py`）一行透传——或 v1 明言不做页内代码块开关，config 字段仅留语义（计划期拍一句）。
- **不进 config 的**：单个档位（查询期决定，不是策略）；`tier_on_no_result`（**评审撤项**，见上 F1 对齐注③）；**BM25 权重调参 / trigram 表 / `rank` 默认配置**——10-15 §2 白纸黑字列在"不在范围内"，别因为顺手要做设置页就把那个坑挖开。
- **诚实标注接入成本**：`search:` 一旦进设置页，自动继承"页面改与手改 yaml 互不打架"契约 + 校验即启动校验 + 乐观并发 409 + `test_routes_order` 快照更新 + 表单项级 422 定位映射（`section: "search"`）。**加三个字段不是加三个输入框。**
- 文案纪律（settings §6）：分段标题统一「检索」，正文不写"落盘/热生效"这类实现 meta。

## 6. 隐私过滤可见性（安全红线对照）

**问题**：`privacy.dirs` 挡掉的文档在搜索结果里**静默消失**。后果不是安全问题而是信任问题——用户搜不到 → 以为自己没写过 → 或怀疑索引坏了 → 半天排查。

**v1 呈现**：结果区末尾一行弱色小字（`--ink-soft` 12px），**条件式措辞**：「若相关文档在隐私设置中，已被排除」；零结果时并入 §4 空态句。**不带计数、不带任何名称/路径/数量**。

- 零内容泄露：连计数都不出，满足红线 5（隐私面仅 display-only 口径）的**收紧**方向。
- 已足够解决上面的信任问题（"是不是被过滤了"有答案）。
- 后端改动：**零**——前端从「`privacy.dirs` 非空」直接判定是否显示该行。**口径修正（评审）**：这是**过报**而非初稿所说「无命中的被滤文档不触发提示」的漏报——查询与隐私目录毫无关系时该行也在。正因如此措辞必须是条件式（"若……已被排除"）而非断言式（"部分结果已排除"），避免零结果时误导甩锅。若嫌过报碍眼：dirs 状态 + 结果侧信号联合判断进计划期，不改隐私语义。

**为何不给计数（D7）**：web 面 LAN 无鉴权（settings §7 已备案的信任面）。显"该词在隐私目录中命中 N 篇" = **存在性预言机**——任意 LAN 设备查询一个敏感关键词即可确认「主人写过这件事」。这是新泄密面，不属红线 5 现状口径，需单独立项与拍板（§16）。

## 9. 状态、hash 与转场

- 状态：`view: 'home' | 'doc' | 'search'`（新增）；`drawer: null | 'file' | 'trash'`（`search` 移出值域）。**评审勘误：初稿值域里的 `'monitor'` 是错的**——监控从未并入 drawer（T3 批准偏离，AGENTS 在案，双实例=双轮询之祸），`state.monitoring` 原样独立旗标，本稿不重开已决事项（照初稿执行会打碎 `test_monitor_tree_slot_exclusion` 等以 `state.monitoring` 为锚的钉）。immersive-shell §4 全局规则①「openDoc 一律关闭文件/搜索/监控抽屉」中"搜索"一项作废，改述为"openDoc 时 `view := 'doc'`"——语义回归其本意。
- hash：进检索页 `history.replaceState('#search')`——**评审改判：初稿 pushState 作废**（pushState 制造 #search 历史条目，back 键语义 spec 全没写，而全仓 hash 纪律是 replaceState；replaceState 下 back 行为与换文档同构，零新语义面）。退出侧修正：**回文档时由既有 `watch(currentPath)` 自动写回 `#doc/…`，只有回 Home 才清 hash**（`replaceState(null, '', pathname)`，首页 spec B1 手法）——初稿"退出必须清 hash"言过其实。**双向都要钉**：
  - `applyInitialHash` 须认 `#search`（F5 停在结果页）；
  - 不得撞上 `app.js` hash watch 的 `if (!p) return` 早退（首页 spec 踩过的同一坑，换锚后复发概率高）。
- **hash 可用之三补（评审阻塞级；三缺一退回"无 hash"方案，监控先例兜底）**：① 移动 boot `applyInitialHash` 遇 `#search` → **忽略并 `replaceState` 清光**（`#settings` 关闭侧先例）——hash 是共享 URL 面，桌面存的书签在移动打开不得起死旗标；② `Ctrl+K` handler isDesktop 门（§8）；③ `watch(isDesktop)` 桌面→移动清零行**加 `view`**（AGENTS 跨断点铁律：旗标所在壳被 v-if 卸载的同点必清零）。
- **退出目标**：`view==='search'` 前若在看文档 → 回那篇文档（含 dock）；本来在首页 → 回首页。不留"退出后一片空白"的中间态。
- **转场**：doc ⇄ search 复用 `.doc-enter` 溶解（immersive-shell §6 先例）；因两视图同宽同顶线，**溶解即已足够沉浸**，不做横向滑动（横向位移会把"原地换内容"变成"翻页"，视觉成本高于收益）。reduced-motion 直切。
- 组件复用：`SearchPanel.js` **原地升格**为页面形态（容器换 + 结果模板按 §4 重做 + 档位 chip），逻辑（防抖/键盘）不换名，避免无谓 churn；实施期若改名 `SearchPage.js` 需同步审计钉文件名（注意 §14 形状钉）。

## 11. 配色预算：一处豁免 + 一条新规则

[[1-项目/md-repo/review/2026-11-23-immersive-shell-color-review]] 定的「一屏黄铜语义单元 ≤3」**对检索页不成立**——满屏 `<mark>` 命中高亮天然几十个。豁免必须换一条可执行的规则：

> **每张片段卡内：首处命中 = `brass` 22% tint 底（实现期目检后自 12% 上调——12% 浅至不可辨，22% 目检认可；2026-11-24 对实现回填）+ `--ink`；同卡后续命中 = `--ink` 600 字重，无底色。**

- 依据：高亮的职责是"告诉眼睛往哪看"，不是"把所有匹配处都标出来"。首处命中正是落眼点，后续命中加粗足以指路。
- 效果：黄铜底块数从 **O(命中数)** 降到 **O(卡片数)**（一屏 ~5–8 块，可控）。
- **这是对 10-18「匹配词高亮（`<mark>` 黄铜色系）」的实质修订**，实施期须同步改该 spec 或在本稿标注取代关系（本稿即取代方）。
- 页内黄铜的其他消耗已压到最低：相关性条退役、heading 去 pill、active 态 8% 浅底 + 2px 条。

三主题：`mark` 底色用 `color-mix(in srgb, var(--brass) 22%, transparent)` 直取即可（**不涉及暗金**，故不吃 color-review §6 那条 dark 下掺墨失效的风险）；正文对比度在暗金底上仍须 ≥4.5:1，列入目检。

## 16. 演进位（不做，但承重）

- **三页共享骨架（含 Home 对齐）**：需 Home 侧改顶线版式 → 破「Home 零改动」契约，须由 Home 会话执行；届时 `--col-topline` 三变量直接复用，边际成本已在本稿付清。**挂账（评审）**：`--col-measure`（680）出生即豁免 Home（720px 自有宽度 + 自有 `hb-scroll` 滚动层），三页对齐波再议单档或双档。
- **隐私命中计数**（D7 弃项）：主人视角更有用，但构成 LAN 存在性探针；启用前需单独拍板 + 是否绑定身份通道。

## 17. 实施注记（不确定点留给计划期）

- `--col-measure` 定值 680px（= EditorPane 列 `max-w-[680px]` 现值）：实施期只需**一次确认两者相等**，不再"先测现值再定 token"（评审已测：初稿担心 token 与现值打架，实测同值）。
- 摘 padding 后的列心对称：1024 / 1280 / 1440 三档目检复核（与 immersive-shell §13 FAB 避让目检合并同一次做）。
- 分组列表的 DOM 迁移：搜索页 ⇄ 文档页是两个子树共存 `v-show`（保留结果状态，推荐）还是互相卸载重建（更省内存但每次重渲染）——`v-show` 优先，代价是搜索页大列表常驻。scroller 各自实例（§3 同几何不同实例），滚动保位不因此失效。
- 内联级正则渲染的转义次序（**评审给出可钉管线，取代初稿"先转 HTML 再套标签"——那句话照字面做会出错**）：**单趟总 regex（alternation：`` `code` `` | `**强调**` | 行首 `#` | 命中词）+ callback 内逐段 `escapeHtml` 再包标签**——code span 分支排前天然免疫「代码内星号被加粗误伤」，逐段转义天然免疫「查询词命中 `&amp;` 实体内部被插标签打碎」。纯函数化进 `utils/`，node 直 import 测（`chatEvents.js` 先例）；XSS 样本钉必上（vault 内容虽是自己写的，但 web 面无鉴权即不可信源）。
- 最近搜索词的条数与去重策略：≤3 条、新词前移去重、满则 LRU 挤尾；只存词不存结果（隐私与体积）；清空入口计划期定一句。
- `top_k_default: 12` 是按"分组后 ~4 个文件"估的；目检后若仍显多再调，值本身在 config 里，不是硬编码。
- 档位 chip 手动换档 = 新请求 = 新一行落账（F1 允许形态），**不要做"同查询多档合并落账"的"优化"**——那会破 11-13 §3 F1 不变式（§5 对齐注）。
- 「加载更多」（若有）走 `top_k_max` 运行时 clamp（§14 裁决），不是新端点也不是分页协议。
