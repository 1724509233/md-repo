# 可逆自动化：记忆运行时 v2 架构设计（终版）

**日期：2026-10-25 · 状态：送审（v1 稿已经 3 轮追问修订 + @oracle 原则评审，本稿为裁决并入后的终版决策集）**

**文档定位**：对 `projects/md-repo/docs/memory-runtime.md`（v0.1 宪法）的架构演进 spec。v0.1 回答「谁有权动」；本文回答三个问题：**动了能不能回来、会不会偏、审起来累不累**。产物 = 宪法修正案（§九）+ 实施分期（§八）。

**评审记录**：@oracle 以产品最初设计原则为标尺逐条裁决——0 违背、11 一致、1 改道（summary 落点，见 §九.4）；深审四刀（§四）、摩擦坑与通知纪律（§六.4）、盲区三则修法（§三.2 / §三.3 / §五.2）均已并入。

## 一、背景：三个实证 + 一个根立场

### 1.1 实证（2026-10-25 事件链）

1. **审计 ≠ 恢复**：`reversible` 是 frontmatter 里的**声明**，不是**机制**——5 个落地 handler 中没有一个逆操作，状态机无 merged→撤销迁移，账本存元数据 + hash 不存内容。授权通过后系统只能审计，无法恢复。
2. **结构校验缺口**：10-24 两条 adopted 提案（`payload: null` / `source_refs: []`）落盘后卡死——写入口只校验信封，不校验动词参数；畸形意图直到执行时才暴露。（执行器侧已修，见 `2026-10-25-adopted-card-visibility-design.md`；本 spec 把校验前移到写入口，见 §五.1。）
3. **反馈环缺接收方**：executor 的裁决（merged / failed + reject_reason）只回显给人，产出它的 agent 读不回。数据建了，消费者没建。
4. **补充实证（本轮代码核对）**：`_merge_link` 现在**写用户源文档**（往 `<!-- related -->` 块追加 `[[target]]`）——「事实区不可写」与现行代码直接矛盾；提案的 `actor` / `run_id` 由 **agent 自报**在 frontmatter 里，越权守卫与回滚分组都建立在可伪造的值上。

### 1.2 根立场（宪法级）

> **用户区（用户原文）对自动化字节级零写；其余一切是派生状态，必须携带与事实的显式有效性关系；每次不可逆操作留下可恢复的凭据；agent 引导思考，不替用户思考。**

**意外收获**：可逆性与交互性是同一枚硬币的两面——动作加法化、可逆化之后，agent 对「实时回包」的需求同步萎缩。v2 用加法动词消解 ReAct 缺口，不建双工通道（§七.3）。

## 二、分层：用户区 / 机器区一刀切

v0.1 三层（法律 / 本体 / 账本）保持，本体层按**读者 + 可变性**重新划界：

| 区 | 介质 | 可写者 | 内容 |
|---|---|---|---|
| 法律层 | `config.yaml` | 人 | 角色注册表（+ `verbs` 声明）、预算、trigger |
| **用户区** | vault 用户笔记 | **人** + 交互 agent（user-ask 确认制）+ rebase（人发起） | 用户原文。自动化对其字节级零写 |
| **机器区** | `index/` + `.sync/` | 唯一执行器 + 提案机制 | entities、summary 双形态、勘误卡、快照库、账本 |
| **提案区** | `suggestions/` | **系统独占重投影**（人/agent 均禁写） | 账本记录的**只读投影**（`projection: true`），供 Obsidian 浏览 |
| 账本层 | `.sync/index.db` | 系统 | changelog + **提案记录表** + **relatedness 表** + 快照索引 |

边界纪律（新增/修订四条）：

1. **用户区零写**：工具边界硬编码路径守卫——agent 与执行器的写调用目标 ∉ {机器区, 提案区} 即拒绝。用户区的合法写路径只有三条：人、交互 agent（user-ask）、rebase（人确认）——全部快照保护。
2. **提案区只读投影**：`suggestions/` 文件是账本记录的确定性渲染，重投影 = 系统独占写、幂等覆盖。frontmatter 首行 `projection: true, source_record: <id>`；控制台对提案的一切「编辑」入口指向账本记录而非文件（盲区 1 修法，§三.4）。
3. **provenance 由 handler 盖章**，agent 不可伪造（派生文件 frontmatter 由落地代码写入，不是提案 body 透传）。
4. **介质跟着读者走（判例化）**：同一事实可以有多个介质副本，**事实源介质由读者决定**，副本必须可确定性重建。relatedness 进 DB（机器读 + 控制台）、快照进 `.sync/`（机器读）、投影文件（人浏览，事实源在 DB）。此句用于挡住未来「为了好看把事实源搬回 markdown」的回潮。

**agent 产出可见性**（摩擦决策，§六.4）：agent 工作产物**不出现在 Obsidian**（related 块退役、勘误进机器区、summary 进机器区、机器边不进图谱）；注意路径 = 控制台 + **打包推送**（§六.4 通知纪律）。被动散落 → 主动推送，注意摩擦不换回。

## 三、可逆：工具边界快照（用户反提案，替代 per-verb receipt）

### 3.1 机制：调用粒度快照 + 条件回滚

**每次不可逆工具调用**前（覆盖两条路径：① agent 直写 `write/edit/move/delete`（user-ask 通道）② 执行器落地合并），把该调用**触及的全部文件**的全文 pre-image 存入 `.sync/snapshots/<call_id>/`，记录 `call_id`、类型、触及路径清单、每文件 pre/post hash、actor、run_id。

- **回滚 = 恢复 pre-image**，单位 = **一次工具调用**（批量调用覆盖全部触及文件，原子恢复）。
- **原子恢复协议**：先全量校验（当前 hash == 快照 post-hash 逐文件比对）→ 后全量写；单文件原子写；任一失败立即停止，surface 半面状态给人——不静默完成一半。
- **撞车守卫**：任一文件当前 hash ≠ post-hash = 后续写已覆盖，**拒绝盲写**，surface「该位置在 <call> 之后被 <actor> 修改过，回滚 or 重新生成，人拍板」。回滚撞后续写，系统不自己选边。
- 整批回滚（按 run 逆序批量调单调用回滚）= v2b 便捷入口；v2a 只有单调用回滚（机制本体）。
- **捕捉范围（P1 gate 钉死，D20）**：LLM 通道全部（agent 五工具 + 执行器五 handler）+ 人类通道仅删除（Web UI）；人类自编辑/移动不捕捉（用户自己的动作，Obsidian 版本历史兜底）。扩展触发条件 = 控制台出现自动化驱动的编辑面，或用户提出自编辑 undo（按 api.py 既有模式机械扩展）。MCP stdio 通道是独立长驻进程，其写路径（write_doc/edit_doc）P2 接线同一捕捉模式（R1），finalize 的降职+认领**收敛为单条原子 UPDATE**（共享 autocommit 连接上 `with conn:` 不开事务——P2 gate 实证 no-op；跨进程原子性 = 单语句 + SQLite 单写者）。
- **确定性引用重写不在捕捉范围（D21）**：move 顺带对引用方文档做的 `[[old]]→[[new]]` 链接重写是确定性、可再生的（重跑 reference update 即复现）——捕捉对象 = 被移动文件本体，不可再生面。

**回滚语义分区**：

| 目标 | 回滚手段 | 理由 |
|---|---|---|
| 用户区调用 | 快照恢复（默认开，强制） | 不可再生，pre-image 是唯一凭据 |
| 机器区 · 确定性产出（entities、投影） | **重新生成**（修规则 + 重跑）；快照默认关 | f 可确定性重建，pre-image 价值≈0 |
| 机器区 · LLM 独一产出（summary、报告、勘误卡） | 快照恢复（**强制开**，即使区域关） | 重跑不必然复现，pre-image 是旧内容的唯一存档（槽覆盖时旧 summary 全文即此 pre-image） |

**保留策略（钉死，盲区 2 修法）**：

- **每文件至多一个活 pre-image**（该文件最近一次写入的 pre-image；新调用覆盖旧快照）——回滚 = 回到上一次调用前，单活快照语义够用。
- **删除类快照单列保留**至人确认清理或 N 天（默认 30 天）。
- **GC 只允许删「被更新快照取代」的旧 pre-image，永不删活的那个**——写成测试锚点（§六.2）。全文历史在账本 hash 链 + 版本控制里，不在快照库职能内。
- **in-flight 行（已捕捉、写未确认的崩溃残留）GC 永不回收**：crash 每写至多留一条，它可能是该文件唯一 pre-image——删除 = 静默销毁恢复凭据（P1 gate B1）；该行保持可回滚（按 call 查批不过滤 live/finalized）。
- 不设保留策略 = 「可回滚」随时间静默失效，「reversible 是声明不是机制」复发，这次轮到保留策略。

### 3.2 删除

- 自动化无删除权：**`delete_doc` 从 bgagent 工具注册表硬摘**（不是配置白名单——配置是卫生，注册表是机制）。
- 交互 agent 删除 = user-ask 确认制（现行）+ 快照兜底（全文进删除类快照）。
- 不做「物理保留 + tag」：unlink + 全文快照，Obsidian 不残留「已删」文件，代码同一条快照路径。

### 3.3 身份 / 来源 / 调用链：三条硬编码守卫

不设计，落守卫：

1. **可信盖章**：`propose` 工具调用时 runner 用 run 上下文覆盖 frontmatter 的 `actor` / `run_id`，agent 自报值不存在（写入口即消灭冒充，不等执行器）。
2. 执行器与回滚分组只信盖章值。
3. **越权拒绝**：提案 `type` ∉ 产出角色的 `verbs` 声明 → 在 `propose` 工具调用时拒（操作化的 reject_reason 返回给 agent）。

### 3.4 不可逆行为的预算（收敛到两个人入口）

自动化能触达的不可逆面只剩：**① rebase**（人确认的 fact 改写，全文快照）；**② 有损压缩的 summary**（人终审 + 槽覆盖 pre-image）。auto 通道全部是「可再生 / 可删行」的机器区写。删除动词对自动化永久不存在（§三.2）。

## 四、动词目录（整表替换 v0.1 §5；@oracle 深审四刀并入）

| 动词 | 目标 | 落地 | 逆机制 | 通道 | LLM |
|---|---|---|---|---|---|
| `entity_index` | 机器区 `index/entities.md` | upsert `## entity` section；**schema 固定 `{entity, attrs: {字段:值}, source_refs: [用户笔记路径]}`，value 禁散文** | 可再生 + （区域快照默认关） | auto | 否（上游产出） |
| `relatedness`（新，替代 link） | 账本库 relatedness 表 | 插边 `(源, 目标, 依据, run_id, ignored)`；**只进索引，不进文件** | 删行 / ignored 标记 | auto | 否 |
| `summary` · 缓存型 | 机器区 `<stem>-summary.md`（一源一槽） | 槽覆盖，旧全文 = 该调用 pre-image | 一键再生成（LLM 重跑）+ pre-image | 终审 | 是（上游） |
| `summary` · 报告型 | 机器区 `<date>_summary_<slug>.md` | 独立文件；**逐断言行强制 source_refs，执行器/校验器缺 refs 拒收**；标题固定 advisory 框架（「分析认为…」） | pre-image（点态不可再生） | 终审 | 是（上游） |
| `errata`（新，替代 correction） | 机器区 `index/errata/<stem>.md` | 加法卡（§四.3 形态）；**原文永不改、不加指针** | 删卡 | 终审 · 单闸门（adopt = 确认） | 否（候选是上游产出） |
| `rebase`（新） | **用户区** | 人确认后改写原文（errata 落地为 rebase 时才发生） | 全文快照 | **仅人触发** | 否 |
| `unmerge`（回滚） | 任意 | 按 §三.1 协议应用快照逆 | 自身即逆操作 | **仅人触发** | 否 |
| `reminder` | 无落地（v1 刻缺） | 控制台通知卡 | — | 终审（无 handler，保持） | — |

**退役三件**：

- **correction 退役** → errata。精确替换动词拆为 `errata`（加法式，agent 可提）+ `rebase`（改写式，仅人）。stale/ambiguous 的精确匹配重试环（10-24 卡死事故根源）随精确替换动词一起消失。存量 correction 提案人工处理，不迁移。
- **link 退役** → relatedness。in-note `<!-- related -->` 块停止追加（用户判「不优雅」）；存量块不清洗（无害）。agent 发现的相关性 = 检索性事实，进 DB，不进用户文件。
- **archive 退役** → 哨兵降级为**只读报告**（「N 篇 90 天未动，建议归档」）；实际搬动 = 人在 Obsidian 拖，或交互 agent 代劳（user-ask）——自动化不搬用户区文件。连带清账：v0.1「归档建议批次」、现行代码 `archive ∈ AUTO_TYPES`、v1 spec「archive 终审」三处并存版本一并废止。

### 4.1 entity 的消费面（结构化 vs 替用户生成记忆的分界）

value 字段化 = 结构化；value 散文且与用户笔记同池竞争排序 = 替用户生成记忆（标尺违背）。因此：

- 召回中 entity 只当「实体 → 用户原文」的**路由/锚**（attrs 是字段，不是叙述）。
- **不变量**：derived 记录（entities、summary、relatedness）在召回排序中**永不排在同源用户文本之前**（§六.6）。

### 4.2 summary 双形态（性质不同，授权不同）

- **缓存型** = 对用户自己文字的可再生有损压缩 = 结构化，但有界风险「用户读摘要替代读原文」。终审（不动）；差异化给**再生性**：stale 自动降级 + 一键再生成，错的成本封顶。
- **报告型** = 跨文档综合根因（10-24 排查文档的正规形态）= **在生成新知识**（用户没写过的因果判断），以**假设**面目出现才合规：(1) advisory 标题框架；(2) 逐断言 refs（执行器结构校验：refs 非空 + 文件存在；**语义性引用-支持度校验 = v2b 候选**，NLI 式比对）；(3) 终审 + 机器区落盘 + provenance；(4) **永不自动并入用户笔记**——人复制进主区 = 记忆化动作（交互 agent 可代劳，user-ask）。

### 4.3 errata 的合规形态（机器指出伤口，缝合线由人画）

「你的笔记这里错了，应为 X」= LLM 对**用户事实**的断言，是全部动词里离「替用户思考」最近的。合规形态三层：

1. **只许 surface 矛盾，不许断言对错**。卡形态：
   ```
   ## 矛盾
   notes/foo.md §2 与 notes/bar.md §1 记载不一致
   摘录 A（foo.md §2）：……原文……
   摘录 B（bar.md §1）：……原文……
   ## 候选读法（candidate, by: 校对员）
   应为：……（人确认时可改写）
   ## 理由
   ……
   ```
   「应为」是**候选值、标注出处**；人确认的是「矛盾属实」，候选是待人署名的草稿。
2. **单闸门**：人 adopt = 确认，卡才物化（物化 = 确权）；reject = 不物化。物化后**系统对该卡只读**，所有权归人（人可随时改 / 删，Obsidian 里也是）。
3. **消费 = 并列展示，永不静默替换**：v2b「有效读法」= 召回时原文 + 勘误标注并列呈现；静默替换那一刻机器就在替用户改写他的事实，再可回滚也晚了。

### 4.4 relatedness 的分层呈现（发现是引导，呈现方式决定它是不是断言）

- 记录 = DB 一行：`(源, 目标, 依据, generated_at, run_id, ignored)`。一条 = 文档级关系边，**无文本位置、无文本内容、零落地**（不是逐行修订建议）。
- 呈现（介质跟着读者走）：
  | 读者 | 介质 | 形态 |
  |---|---|---|
  | 控制台（主） | 网页 | 文档详情两块并列：「你的链接」（用户 wikilink）/「机器建议」（DB 行渲染，每条带依据摘要 + 忽略按钮） |
  | 召回引擎 | 直接读 DB | 相关度信号参与排序，无投影 |
  | Obsidian | **默认无** | 可选机器区导出 `index/related-suggestions.md`（`projection: true`，纯渲染） |
- 机器边与用户 wikilink **分列两层**，默认只画用户层；机器边是「建议」层（一键忽略）。
- **忽略 = DB 行写标记**（不是改文件）→ 进遥测 → 固化者回读（忽略过的配对下次少提）——relatedness 的反馈环。
- 全系统「建议」分型（定案）：

  | 形态 | 粒度 | 模型 | 人的动作 |
  |---|---|---|---|
  | relatedness | 文档级（无位置、无内容） | 推荐位 / 检索信号 | 浏览 · 忽略 · 自己写链接 |
  | errata | span 级（old 摘录 + 候选 new） | 修订 / tracked changes | 确认矛盾 · 改写候选 · rebase 落地 |
  | 报告型 summary | 整篇（机器区物化） | advisory 报告 | 读 · 引用 · 复制进主区（= 记忆化） |

## 五、提案：记录进账本 + 创建改工具调用 + 协同终审

### 5.1 数据结构化（D-P1 / D-P2）

- **记录进库**：`index.db` 提案记录表（`id, type, actor, run_id, status, payload(JSON), source_refs, justification, reject_reason, 时间戳`）+ 状态变迁历史表。**状态以账本记录为唯一状态源**；状态机从「改文件」变「改记录行 + 记变迁」。`suggestions/` 文件 = 只读投影（§二.2）。存量 4 条 merged **不导入**（记录从切换日起；无内容 diff 可补，伪造凭据比没有更危险——承 v1 D7 口径）。
- **创建 = 工具调用** `propose(type, payload, source_refs, justification)`：agent 写不了 SQL，提案创建从「写文件」改「调工具」。一步带走三件事：**同步校验**（工具参数即校验点：信封 + per-verb payload schema，畸形**零落盘**、当场报错返回 agent）、**可信盖章**（§三.3.1）、**越权拒绝**（§三.3.3）。`suggestions/` 进 agent 直写禁写名单；10-22 文件级校验钩子（`validate_suggestions_write`）退役，换工具级。
- **待审队列 TTL**：`awaiting_review` 自创建起 14 天未审 → 自动转 `expired`（actor=system，变迁记账）；回读注入的未决计数不再挂僵尸条目。（10-27 联审补入：实施先行，裁决认下。）
- 控制台从扫目录改读库。

### 5.2 协同终审（D-P3，主 agent 无缝作为终审协作者）

- 主 agent 四个工具：`list_proposals(status?/type?/actor?)` / `get_proposal(id)` / `adopt_proposal(id, note?)` / `reject_proposal(id, reason)`。与控制台 adopt/reject API **同一条代码路径**（`decide_record()`），行为必然一致。
- `get_proposal` 返回**审读摘要**（不是原始文件）：动词、校验过的参数、影响描述、风险级、justification。
- **红线（三条，框架级不是提示词）**：
  1. **agent 只做决策支持 + 执行，不做决策**；auto-triage（agent 自动过掉低风险）明确范围外。终审通道存在的理由就是产物不可逆/承载语义，把人的闸门换成 agent 的闸门 = 授权分层静默降级。
  2. **谁在说话不可混淆**（盲区 3 修法）：摘要的 justification 区块**原样引用提案原文并标注「以下由 <角色> 生成」**；摘要新增的风险评估标注「以下由 主agent 生成」。防止人点头的对象从「提案本身」滑移成「agent 的转述」。
  3. **不得批量 adopt**：对话渠道逐条确认，无「全部采纳」快捷路径（批量是滑移的最短路径）；每次对话渠道 adopt 在 changelog 写显式回执 `actor: human, via: 主agent`，立法痕迹上把「人判」钉死。
- **落地预演（D-P4）推迟 v2b**：用户区零写后「用户文档将发生什么」恒为空，机器区有快照兜底，预演是第二层保险。v2b 范围收窄为「vault 漂移时 surface」（大部分已被 stale 检查覆盖）。v2a 的合并时复算只做结构校验（source_refs 存在性 + hash），漂移 → surface 不盲落。

### 5.3 回读注入（框架级反馈环）

runner 每次 run 在上下文头部注入本角色：**未决 N 条 / 失败 M 条（含 reject_reason）/ stale 派生 K 条（v2b）/ 被忽略的 relatedness 配对（遥测）**。有界（top N + 截断标注）。提示词自律不可审计，框架注入是硬约束——run N 的失败必然在 run N+1 的上下文里。

## 六、人在回路：四个位置 + 摩擦核算

| 位置 | 时机 | 动作 | 变化 |
|---|---|---|---|
| **立法者** | 事前 · 规则级 | 写/改 config.yaml（角色、verbs、预算、trigger）；UI = 编译器 + 校验器，文件唯一事实源 | 不变 |
| **终审者** | 事中 · 产物级 | 只审两类：**summary（双形态）+ errata**。位置不变（人判），**位置搬家**：对话（agent 预消化 + 材料）与控制台双通道 | 终审面从 5 动词收敛到 2；信息加工量从「人读 schema」降为「听摘要」 |
| **抽查者 + 回滚者** | 事后 · 回滚级 | 看流水/投影；不满意 → 单调用回滚（带撞车守卫）；忽略机器建议 | 新增：可逆产物上，人从事前审批移到事后抽查 + 一键回滚 |
| **书写者**（明示） | 随时 | 人复制报告/勘误进主区 = 记忆化；人写 wikilink = 把机器建议转正；rebase = 人发起 | 「引导不替想」的落地：agent 产出转正永远是人的书写动作 |

**摩擦净核算（@oracle）**：净下降。省掉：correction 精确匹配重试环（10-24 事故根源）整个消失、link 往笔记插块的侵入感消失、终审面 5→2、误 merge 的恢复从「审计都做不到」变一键 pre-image——削减都发生在用户最痛的点（agent 动我的原文）上。**坑**：产出可见性从「散落在笔记里」收拢成「只剩控制台」= 注意摩擦**集中化**而非消除，主动查的频率随时间衰减。

### 6.4 通知纪律（坑的修法，兑现 v0.1 §8 承诺）

每条进入终审面的提案（summary / errata）+ 每份哨兵 / 叙事者报告 → **推送打包终审材料**（内容 + 来源 + 处理结论 + 相似比对）+ 深链直达控制台该卡。一条一推，克制（防「通知退化成我爱你第一千遍」）。被动散落 → 主动推送，注意摩擦不换回。

## 七、bgagent 端到端：能力与约束

### 7.1 角色契约

`name / prompt / scope / 工具白名单 / budget / triggers / escalation`（承 v0.1）+ **`verbs: [...]`**（动作空间显式声明，越权守卫的依据）。

### 7.2 工具面

| 类 | 工具 | 说明 |
|---|---|---|
| 读 | read / search / list_files / recent_changes | 实时，不变 |
| 读（注入） | — | runner 框架注入未决/失败/ignored 清单（§五.3），不是工具 |
| 写（唯一入口） | `propose(type, payload, source_refs, justification)` | 同步校验 + 盖章 + 越权拒绝；**除它之外无任何 vault 写路径**（直写工具对 bgagent 不注册，`suggestions/` 禁写名单双保险） |
| 无 | vault 直写 / delete / 回滚 / rebase | 删除从 **bgagent 工具注册表硬摘**；回滚与 rebase 人独占 |

### 7.3 执行模式

- **v2 = 队列模式**（事件驱动 executor + 30min backstop，已实现）：批角色 fire-and-forget，观察方 = 人。
- **同步模式（ReAct 回包）缓行，v3 候选**：errata 加法化消灭了最大用例（精确匹配 refine 环）后，剩余动词多为幂等/一次性，反馈价值低；仅当出现迭代型角色时立项。
- 执行器纪律不变：零 LLM 调用、单写者串行、trigger 防自触发、arm ≠ run、budget 闸门。

### 7.4 席位映射（动词归位后）

| 角色 | v2 动词 | 备注 |
|---|---|---|
| 固化者 | entity_index / relatedness / summary 双形态 | trigger 增加 stale 武装条件（v2b）；回读注入含 ignored 遥测 |
| 哨兵 | **无落地动词**（只读报告） | 召回遥测 + 衰减分桶 + 归档候选报告；与叙事者同构（v0.1 §6.3「归档建议批次」退役） |
| 叙事者 | 报告（非提案，只读产出） | 天然可逆，零风险 |
| 校对员（新席位，v2b 候选） | **errata** | v0.1「按需追加」的动词基础；只 surface 矛盾、不提改写式修正，爆炸半径 = 机器区一张卡 |

### 7.5 硬约束汇总（框架层强制，非提示词自律）

1. 用户区对 agent 与执行器字节级不可写（路径守卫，§二.1）
2. 写提案 = propose 工具，同步校验 + 盖章 + 越权拒绝（§五.1）
3. bgagent 注册表无 delete、无任何直写工具（§三.2 / §7.2）
4. 每次 run 上下文注入未决/失败/ignored 清单（§五.3）
5. provenance 由 handler 盖章（v2b 接线，机制 v2a 落位）
6. 防自触发 / arm ≠ run / budget / max_proposals_per_run（承 v0.1）
7. 执行器内零 LLM（承 v0.1）

## 九、宪法修正案（v0.1 明文改动六处）

1. **铁律 1 执行面**：唯一执行器的可写面从「主记忆区」收窄为**机器区 + 提案区**；用户区写路径 = 人 / 交互 agent（user-ask）/ rebase（人发起）。位置：v0.1 §四执行器定义。
2. **铁律 2 状态源翻转**（D-P1，全组唯一实质触动铁律的决策）：「suggestion 的 status 以文件 frontmatter 为唯一状态源，DB 不建队列表」→「**提案状态以账本记录为唯一状态源；`suggestions/` 文件为只读投影，重投影为系统独占写，覆盖人工编辑**」。位置：v0.1 §三边界纪律第二段。同时明示边界：存量 4 条 merged 不导入。
3. **介质跟着读者走（判例化新句）**：「同一事实可以有多个介质副本，事实源介质由读者决定，副本必须可确定性重建」。位置：v0.1 边界纪律。
4. **§10 拍板记录 · summary 落点**：「采纳的 summary 进主记忆区」→「**summary 落机器区（缓存/草稿形态）；人把它复制/移入主区 = 记忆化动作**（可交互 agent 代劳，user-ask）」。概念上「采纳的 summary 是记忆本体」仍成立，物化时机从执行器落地推迟到人的复制动作。
5. **哨兵席位**：v0.1 §6.3「归档建议批次」退役 → 哨兵 = 召回遥测 + 衰减分桶 + 只读报告（与叙事者同构）；§5 动词表 archive 行删除。
6. **§5 授权初分表整表替换**（非逐行改）：entity_index 行改（schema 字段化、消费面降级）；link 行删 → relatedness 行增（auto、仅索引）；summary 行拆双形态（终审）；correction 行删 → errata 行增（终审 · 单闸门）；archive 行删 → 哨兵只读报告；新增人的动词 rebase / unmerge（仅人触发）。动词目录以本 spec §四为准。

## 十、不变量（测试锚点，验收标准）

1. **用户区 hash 稳定**：全流程（bgagent run → 提案 → 终审 → 执行器落地）跑完后，用户区文件 hash 不变（测试内排除 user-ask / rebase / 人的动作——这三条是合法写路径）。
2. **快照与回滚**：每个不可逆调用（用户区）有活 pre-image；vault 副本上 dry-run 回滚恢复到 pre-state；**GC 永不删活 pre-image**（构造「新调用覆盖旧快照」场景断言）；撞车时拒绝盲写且 surface。
3. **relatedness 分层**：机器边只存在于账本库与控制台渲染；用户区文件零机器边字节；忽略 = DB 标记且进入固化者回读注入。
4. **写入口校验**：畸形 payload 的 `propose` 调用零落盘且报错返回 agent；越权动词（type ∉ verbs）调用被拒；agent 直写 `suggestions/` 被路径守卫拒绝。
5. **投影幂等**：提案状态只信账本记录；投影文件带 `projection: true, source_record`；重投影幂等覆盖，两次投影字节一致。
6. **排序纪律**：derived 记录（entities / summary / relatedness）在召回排序中永不排在同源用户文本之前。（实现注记，P2 gate：机器区本就 FTS 池外——`EXCLUDED_INDEX_DIRS`（v1 机制）——derived 根本不进召回，测试锚点 = 全流程后 `index/*`、`suggestions/*` 零 segment；排序侧降权在 v2a 是空操作。legacy 用户区 v1 summary → D22。）
7. **生成类动词合规**：报告型 summary 逐断言 refs（缺 refs 的提案在 propose 调用即拒）；errata 候选标注 `candidate, by: <角色>`；确认后召回中原文与勘误**并列**（v2b 接线，v2a 断言卡内容与标注）。
8. **回读注入**：构造 run N 失败（reject_reason 非空），断言 run N+1 上下文包含该失败与理由。
9. **终审红线**：对话渠道 adopt 在 changelog 记录 `actor: human, via: 主agent`；不存在任何批量 adopt 代码路径（静态断言）。
10. **LLM 独一产出强制 pre-image**：机器区快照默认关配置下，summary 槽覆盖 / 报告 / 勘误卡落地仍产生 pre-image（旧全文可读回）。

## 十一、范围外（明示不做）

1. **agent 自主撤销 / 自主 rebase / 批量 adopt**：人独占（§五.2 红线）。
2. **auto-triage**（agent 代终审）：范围外（§五.2 红线 1）。
3. **同步 ReAct 回包**：v2 不建（§七.3）；加法动词消解了主要需求，迭代角色出现时再立项。
4. **多文件事务 / 目录改名 / 删除**：执行器保持单文件粒度；自动化无删除权（§三.2）。
5. **事实 vs 事实矛盾的自动裁决**：只 surfacing，裁决是人（v3 检测，裁决永远人）。
6. **存量合并的回滚**：快照与提案记录从切换日起；存量 4 条 merged 不回滚、不补凭据、不导入。
7. **前端法条编辑**：承 v0.1 控制台三期排期，不与本 spec 耦合。
8. **用户区 ghost text / 行级修订建议**：机器不提议对文本的编辑——全系统唯一的 span 级建议是 errata（§4.4 分型表）。
