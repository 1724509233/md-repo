# 中断语义与 stop 信号：半截输出、思维链的价值分层（思考记录）

状态：**讨论沉淀，非 spec**。两条落点通道均未排期；相关边界在 run-detach spec §9 备案，链接互钉见文末。
触发：运行脱离连接目检后用户实测讨论——「中断时的前端残留输出和刷新恢复后的展示不一致，因为半截输出会被丢弃」。

## 1. 机制事实：中断到底丢什么（代码锚点，2026-11-20 核对）

runtime 的 append 粒度是「每次 LLM 调用结束」：

- assistant 行（text + tool_calls）在调用完成时入 `agent.messages`（runtime.py:335 终答 / :349 派发）；在飞调用的流式累积在 cancel 时**丢弃**（runtime.py:269 注释明写 "accumulation is discarded"）。
- tool 结果行逐条实时入（:421/:454/:480）；stop/crash 分支的 `_save_and_boundary` 把 agent.messages 现状原样落库。
- 孤儿 tool_call（tool 执行中被掐）：显示侧 `chatRestore.js` 封 error 态；LLM 侧 `_ensure_tool_results`（runtime.py:105）在每次模型调用前补合成结果，保 API 合法 + 防重放（bug b621b5b4 机制）。
- 文件写入另有 change_ledger 全审计（source + actor + pre_hash），与中断无关地完整。

**结论：真正丢的只有两样——当前在飞 LLM 调用的半截文本流、全部思考链。已完成的工具事实全部存活。**

## 2. 半截输出的价值分层（三层，每层答案不同）

1. **UI 连续性**：硬伤级。看过的字重进即蒸发 = gaslighting。该修。
2. **模型续跑**：价值最高。「方向不对改成 X」「我做了一半你来验证」——模型历史里若没有自己的半句企图，「继续」只能从头猜。应以 `interrupted: true` 标记的 assistant 行入历史（主流产品既定做法）。
3. **追溯**：有价值但必须降级——半截文本是**模型的宣称（claims about intent），不是证据**。它说「我现在要把 X 写入」然后转向，按字面追溯即被误导。事实层（工具行 + 台账）已在，半截文本只是叙事补全，不得升格为审计依据。

元论据（用户当场演示）：本次讨论本身发生在用户中断助手半截输出之后——若半截被丢弃且页面刷新，「另外补充」将指向一段模型从未见过的上下文。会话不连续的荒谬即是第 1、2 层价值的存在证明。

## 3. stop = 用户意图信号（零摩擦强标签）

与既有反馈体系的关系：verdict（D21/D22）需要点击，稀疏且迟；**stop 免费、高频、强负标签**。可解构的信号族：

- **停留时长**（submit→stop dwell）：3 秒即停（方向一眼错）vs 90 秒停（慢/中途跑偏）含义不同。
- **停止落点阶段**：确认挂起上（显式的无声拒绝——与 300s 超时自动拒绝同一语义的显式版）/ 工具执行中 / 文本输出中。
- **停后紧跟的补发原文**：用户的澄清/追问就是免费标注——哪里没懂、哪里错了，instruction-following 修正对。
- **停后同义重问**：上一轮整体失败的强标记。

归因契约现成：stop 走已鉴权 HTTP 面进 RunHub，trigger 由通道盖戳（安全红线 3：身份由通道背书），永不来自模型或请求参数——与 verdict 落账同模式。

## 4. 思维链作提示词优化原料：选段、隔离、闭环

思考链今天从不持久化（reasoning 仅事件流，runtime.py:237-246；DB 零字节；`mapHistory` 不产出思考块）——完成轮也一样。采集策略：

- **选段**：全量持久化 = 成本大库、价值稀薄（成功轮长链无人回看）。富矿在失败处：**stop / error / 确认超时轮**的链，尤其末段（转向发生地）。按触发条件抓取，非常开。
- **隔离**（红线 5 三点齐全）：走旁路账本，**绝不回喂 LLM 历史**（reasoning 入上下文污染，多数端点直接报错）；新表进 `ledger.db`（权威、不可重建，与 proposals/snapshots 同族）；不进 FTS / recall / relatedness / agent 读工具（session 表本就在这三个面之外，照抄其隔离）；保留期 GC 30 天，仿 trash/snapshots 先例。
- **闭环**：原料不落账不消费等于没采。消费端是系统现成的形状——bgagent 定期读近期中断信号 + 当时半截文本 + 停后补发原文 → 摘要写 `projects/md-repo/review/` 或提案通道。用户写的提示词，被用户中断过的每一轮都在替它压测。

## 5. 落点建议（两条通道，均未排期）

- **通道一（小增量）**：在飞半截文本以 `interrupted: true` assistant 行落库——修显示不一致 + 解锁「继续」。改动小、语义清晰；待决参数：是否附带停后补发轮的系统提醒（如「上一轮被用户中断」）、tool_calls 半途形态的落库口径（现由孤儿封 error 兜底，可不动）。run-detach 合入后做。
- **通道二（独立功能）**：stop 信号账本（run_id/session/trigger/dwell/落点阶段/停后首条补发/是否同义重问）+ 失败轮思考选段 + bgagent 消费闭环。待决产品参数：思考抓取长度上界、保留期、dwell 阈值口径、同义重问的判定归谁（离线消费侧判，不进账本）。

与既有备案的关系：spec §9「观感分叉（评审 m7）」是本问题的同族——live 显示与持久化真相在取消窗口分叉，当时的口径是「以持久化为准」；通道一本质是把半截文本拉进持久化真相，让分叉面收缩。
