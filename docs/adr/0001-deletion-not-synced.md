# 删除不同步、被删且远端改动过的文件会被重新拉回

删除被当作本地操作而非需同步的状态：客户端删除文件后，该路径只是从其 client manifest 中消失，服务端保留该文件。后果是：若该文件同时被另一端修改过，compare 会把它归入 `to_pull`，用户删掉的文件会在下次 sync cycle 回来——已确认可接受，因为回来的是带远端修改的版本，对单人使用是增值而非噪音。

曾考虑的替代方案是 tombstone（把删除本身作为一等实体同步），被拒绝：需要同步墓碑、还要处理「墓碑 vs 同名新文件」的冲突，协议膨胀对单人 LAN 场景不成比例；再删一次的代价足够低。
