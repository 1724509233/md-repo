# 选区 → 源码编辑（Select-to-Source Editing）

- 状态：定稿（2026-11-10，oracle 一致性审查通过，F1–F5 定稿条件已解决；功能代码待 §8 十二条浏览器目检后随 block-editing 提交）
- 日期：2026-11-09
- 独立成文：不继承、不引用任何此前的块编辑方案；本文只依赖应用既有不变量（源码是唯一事实源、提交与 textarea input 同通道）。

## 0 背景与目标

- 手动编辑是**低频、小范围**行为：文本修正、标题/结构小改、删除、链接修正、打 tag。重行为（增量写作、提取、结构化）由 agent 代写。
- 被否路线的核心风险：原地编辑 DOM 内容后回序列化 markdown，会丢失语义与原始写法（无法表达的嵌套被降级为纯文字 = 静默渲染损失）。
- 本方案：**markdown 源码是唯一事实源，预览是只读投影；编辑永远发生在源码文本上**。不存在「编辑 DOM → 还原 markdown」这一步，因此不存在序列化丢失面。
- 参考：Obsidian live preview 模型——源码字符串为唯一事实源，渲染靠装饰层投影；选区恒为源码坐标；IME / undo / 粘贴全部是原生文本行为（官方 changelog 与帮助文档证实；其 reading mode 完全只读，无「预览选中跳到编辑」路径）。我们的 v1 比它多一层「预览选区 → 源码行范围」映射（§3），这层在 v2（§7）整体消失。

## 1 范围

### 1.1 v1 做什么

| 用户意图 | 入口 | 执行位置 |
| --- | --- | --- |
| 选中单块 → 落源码 | 预览点击块 | 源码模式 |
| 选中跨块范围 → 落源码 | 预览框选 / 拖选 | 源码模式 |
| 文本小改、改标题、改链接 | — | textarea 内源码编辑 |
| 打 / 删 tag | 选中 frontmatter 块 | frontmatter YAML 行编辑 |
| 表格编辑（改格 / 增删行） | 点击表格 cell / 拖选表格块 | 格级：该格文本范围（§5.1）；拖选 = 整表行区间 + 源码编辑 |
| 删除块、合并、拆分 | 扩展选区 | 文本级操作 |
| 提交 | — | 与 textarea input 同通道，零新路径 |

### 1.2 v1 不做什么

- contenteditable 原地编辑（任何形态）
- 浮层范围编辑器（range window）
- 块移动 / 合并命令按钮等结构命令
- 字符级 DOM 选区映射（选区粒度恒为块级）
- shift+click 增选、多区间选择
- CodeMirror 6 / live preview（v2，§7）
- 新保存触发器、新冲突守卫（全部沿用既有）

### 1.3 块类型策略

机制**不做类型分支**：任意有行号映射的块（frontmatter、标题、段落、列表、代码块、表格……）点击均可落源码。v1 验收聚焦 frontmatter + h1 + 段落 + **表格**及跨块组合；其余块类型可用但不列入验收项。

## 2 选区入口（预览侧）

### 2.1 Affordance

- hover 块 → 淡描边；hover 表格 cell → 更淡描边（比块描边淡，提示格可点）。无按钮、无角标、无常驻 chrome。
- 发现性：无常驻 chrome、无首次帮助文案（原设计稿含一次性帮助文案，2026-11-09 用户要求移除）。

### 2.2 手势

| 手势 | 结果 |
| --- | --- |
| 点击块（mouseup 无文本选区） | 单块范围 |
| 点击表格 cell | 单格文本范围（§5.1） |
| 框选 / 文字选区（mouseup 时 selection 非空） | 锚点块 → 焦点块，含中间所有块 |
| 拖选跨块 | DOM 选区 anchor/focus 块 + 中间块合并 |

- 三种手势收敛为同一结果：连续块范围，对应行号闭区间 [L1, L2]。
- 选区跨越渲染内联元素（强调 / 链接 / 行内代码）时，按**所在块**判定，不做字符级映射。
- 操作意图点击不触发落位（2026-11-09 定稿）：活链（委托 openDoc 跳转）与外部链接（新 tab）、代码块复制按钮；死链 / 歧义链无跳转，点击 = 落位（顺势改链接语法）；task list checkbox（disabled）浏览器不派发 mouseup，天然不落位。

### 2.3 失败处理

- 映射缺失的块（行号未解析成功）：无 hover 描边、点击无反应、静默，不弹错误。

## 3 块 → 行定位（v1 唯一新增机制）

### 3.1 机制

- 渲染管线 lexer 遍历时，为每个**顶层块 token** 记录源码行号闭区间 [start, end]（1-based，含 frontmatter YAML 行），写入对应渲染元素属性：`data-src-line`、`data-src-line-end`。
- 行号来源：lexer token 的 `raw` 与文档源顺序对齐（tokens 顺序拼回文档），由 raw 前缀长度推出行号。
- 映射粒度 = 顶层块；嵌套结构（列表项、表格行）由父块区间整体覆盖——不深入嵌套，这也是「无类型分支」的由来。
- 每次渲染一次构建，随文档失效重建；无持久注册表、无写回状态、无增量维护。

### 3.2 不变量

- 行号映射必须与**当前加载文档**一致：文档变更（用户保存、agent 写入、同步拉取）→ 映射整体重建，禁止引用旧映射。重建触发 = 渲染输出变化，或预览态内容变更（渲染不可见的变更——插入/删除空行、`**x**`↔`__x__` 记号互换——可使 HTML 逐字节相同，v-html 不 patch；实现挂 preview 态 `watch(localContent)` 兜住），或切回预览（mode watch）；agent 写入与切模式同 tick 的幂等双写可接受。
- 映射只回答「哪几行」，不参与写回逻辑——写回内容 = 用户敲下的源码文本，逐字。

### 3.3 成本定位

这是 v1 唯一的「块维护」成本，也是 v2 方向（§7）下整体可丢弃的部分：CM6 live preview 中（Obsidian 同路径）选区天然是源码坐标，该层不存在。

## 4 落位（源码模式）

### 4.1 流程

1. 选区确认（§2 任一手势）
2. 切源码模式（既有整文档 textarea）
3. 行号 → 字符偏移（前缀和），`setSelectionRange(L1, L2)`
4. 滚动 textarea 至 L1
5. 焦点进 textarea，立即可输入（替换选区）或继续扩选

### 4.2 可见性与退出

- 可见性 = textarea 原生选区高亮，不另加高亮带。
- Esc / 返回预览：沿用源码模式既有退出行为，本 spec 不新定义。
- 源码模式无入口锁（模式切换按钮恒可用，`setMode` 为裸赋值）；agent 写入与人工编辑的并发安全由脏缓冲保护（agent 内容到达时不覆盖未保存编辑）+ conflict banner（通知性，不阻断）承担，选区手势不被任何守卫拦截，本 spec 不新增。

## 5 编辑语义

编辑全部发生在 textarea 内，均为原生文本操作：

| 意图 | 源码内操作 |
| --- | --- |
| 文本小改 | 直接改字 |
| 改标题 | 改 `# ` 行 |
| 打 / 删 tag | frontmatter YAML 行增删 `tags:` 条目 |
| 改链接 | 改链接行 |
| 删除块 | 选该块行（含尾随空行）删除 |
| 合并两段 | 扩选后编辑成一段 |
| 拆段 | 插入空行 |
| 跨块调整 | 扩选覆盖多块后编辑 |
| 改表格单元格 | 缩窄选区到该格文本替换 |
| 表格增行 / 删行 | 增删整行（列数与表头一致） |
| 改表格对齐 | 编辑分隔行（`:--`） |

- IME 组合、undo/redo、粘贴 = textarea 原生行为（与 Obsidian 同路径：编辑的是源码文本）。
- 编辑后系统唯一动作 = 既有保存路径。无序列化、无规范化、无「渲染语义不变」校验需求——因为从未触碰渲染内容。

### 5.1 表格专项

- **落位**：表格是单一顶层块，**点击 cell → 落该格文本范围**（格内文本，不含左右 `|` 分隔符）；空 cell → 零宽落位（caret 入格）；拖选 / 跨块手势 → 整表行区间（表头行 + 分隔行 + 全部数据行）。映射层仍为块级（§3 不变量不变）——格区间是**点击时纯函数**：DOM `tr/td` 取 (行, 列)，表格源行按未转义 `|` split 推出该格字符区间；无持久格注册表。
- **格编辑 = 替换该段文本**（落位已在格粒度）；扩选到多格 / 整表仍自由。系统对格不做结构假设。
- **增行**：敲入一整行（列数与表头一致）；**删行**：选整行（含换行）删除。列数一致性由用户保证——GFM 下数据行与表头列数不符时多余列丢弃、缺失列按空渲染，**预览即反馈**；app 不做列数校验与补全（无序列化 = 无规范化面，§5 原则）。
- **对齐**（`:--`）= 分隔行的普通行编辑。
- **嵌套表格**（列表项内的表格）：由父块（列表）区间整体覆盖落位（§3.1），v1 不单独处理。
- **渲染**：真应用预览已有表格样式（`#preview table/th/td`：边框、表头底色、行 hover），本 spec 不新增渲染规则；设计稿按既有样式渲染，与真应用一致。

## 6 提交

- 提交通道 = 与 textarea input 完全同通道（既有路径），本 spec 零新提交路径。
- 保存后预览重渲染，§3 行号映射随之重建。
- 冲突（同步冲突、agent 写入）沿用既有行为，不新定义。

## 7 v2 方向（点到为止）

若 v1 验证成立，编辑面迁 CodeMirror 6 live preview（Obsidian 路径）：预览即编辑器，源码字符串为事实源，选区恒为源码坐标，§3 映射层整体消失；§3 的「块 → 行」组件是届时唯一可丢弃件。本 spec 不设计 v2。

v2 候选（本 spec 不设计，仅记录）：表格右键命令（插入行/列）——源码文本变换（行 split、格拼接），不属序列化；新增时需先拍板程序化写入的 undo 语义（程序化写入不进原生 undo 栈）。Obsidian core 亦无此功能（社区插件 territory）。

## 8 验收

1. 预览点击 h1 → 源码模式，`# ...` 行被选中、滚动至可见、可直接输入。
2. 点击正文段落 → 该段源行被选中。
3. 从标题拖选 / 框选到正文 → 选区覆盖两块的行及中间空行。
4. 点击 frontmatter 卡 → YAML 行区间被选中；增一个 `tags` 条目保存 → frontmatter 生效。
5. 删除：选正文块行 + 尾随空行删除，保存 → 块消失，其余文档渲染正常。
6. 合并：扩选覆盖两段编辑成一段，保存 → 预览为一段。
7. 块内改字：改一个词保存 → 预览生效；文档其余部分字节不变。
8. IME：textarea 中文拼音组合正确落字（原生行为回归项）。
9. 映射一致性：agent 写入 / 同步拉取触发重渲染后，点击块仍落对行（无陈旧映射）。
10. 静默失败：映射缺失的块（若存在）无 hover 描边、点击无反应、无报错。
11. 点击表格 cell → 该格文本范围被选中（不含 `|` 分隔符）；替换输入保存 → 预览该格更新，其余逐字不动；点空格 → caret 入格。拖选覆盖表格 → 整表行区间。
12. 表格增行（列数与表头一致）保存 → 预览多一行；删行保存 → 预览少一行，表格渲染正常。

## 9 实现要点（非穷尽）

- **9.1 行号**：marked lexer token 带 `raw`；按 tokens 顺序对齐文档源，累加 `raw` 前缀长度推出每个顶层 token 的 [start, end] 行号。frontmatter（`---` 围栏）、heading、paragraph、list、code、table 均为顶层 token，天然同机制。实测（marked 4.3.0，2026-11-09）：table / heading token 的 `raw` 会吸收尾随空行——`start` 仍由 raw 前缀和推出，`end` 取 raw 最后一条非空行，区间端点不含尾随空行（否则表格落位扩进空行，替换输入会吃掉块间间距）。另：v4.3 的 `marked.lexer(src, opts)` 传部分 options 会**整体替换** defaults 而非合并（gfm 被静默关闭、表格退化为段落），须 `{...marked.defaults, ...opts}`；真应用走 `marked.parse` + `setOptions`（合并语义）不受影响。
- **9.2 token → DOM 对齐**：渲染 pass 中顶层 token 顺序与渲染后 HTML 顶层元素顺序一一对应（frontmatter 卡、h1、p、ul/ol、`div.code-block`、`div.overflow-x-auto`（表格包装）、mermaid 块 = `div.code-block` 内 postProcess 后的 `div.mermaid`），逐对写 `data-src-line` / `data-src-line-end`。真应用 renderer 包装口径（markdown.js）：代码 / mermaid fence 包 `div.code-block`（renderer.code）、表格包 `div.overflow-x-auto`（renderer.table）——映射写在这些包装元素上（它们即 token 的顶层元素）；设计稿演示层用裸 `pre` / `table`，仅 DOM 结构不同、交互语义一致。对齐失败（token 数 ≠ 元素数）→ 该文档整体放弃映射，走 §2.3 静默失败。注意：mermaid fence 经 postProcess 后 `pre` 被**替换**为 `div.mermaid`（真应用 markdown.js postProcess，`pre` 位于 `div.code-block` 内），映射须按 postProcess 后的最终 DOM 写：容器 `div.code-block` 与 `div.mermaid` 同写整段 fence 区间（容器 = 整块 hover / 落位，图 = 渲染图点击的最近命中）；hljs 高亮为原地改 class，不影响元素顺序。
- **9.3 选区手势**：预览容器 mouseup 事件委托——window selection 非空 → `anchorNode`/`focusNode` → `closest('[data-src-line]')` 取两端的块 + 中间块合并；为空 → 光标下元素所在块。
- **9.4 落位**：行号 → 字符偏移用行前缀和一次算出；`setSelectionRange` + `scrollTop` 定位 L1。CRLF 文档（Windows 同步）口径：块级选区不含行尾 `\r`（endOfLine 剔除），防替换输入产生混合行尾；TOC 跳行（路径 A）前缀和按实际分隔符长度（CRLF=2）累加，与 ta.value 实际字符位对齐（get_doc 原样返回、JS set textarea.value 不重新 sanitize）。
- **9.5 失效重建**：映射构建挂在既有重渲染触发点（保存后、agent 写入后、同步拉取后），随渲染一起发生，无独立生命周期。重建可发生于渲染输出不变的内容变更（渲染不可见的变更——插入/删除空行、`**x**`↔`__x__` 记号互换——HTML 可逐字节相同、v-html 不 patch；实现挂 preview 态 `watch(localContent)` 兜住，同 §3.2 口径）。
- **9.6 hover 描边**：块描边 CSS 作用于 `[data-src-line]:hover`；表格格描边作用于 `table td/th:hover`，铜比低于块描边（设计稿：25% < 38%），均为 1px inset shadow、零 reflow；事件委托保证零常驻 JS。
- **9.7 格落位（点击时）**：cell 点击 → DOM `tr/td` 取 (行, 列) → 表格源行（逐行）按未转义 `|` split 定位该格 [start, end] 字符区间 → 行前缀和折算全文档字符偏移 → `setSelectionRange`。纯函数，点击才跑；映射层不存格单元（§3.1）。空格（源文本仅 padding 空白）纯函数仍返回格区间，落位语义层收为零宽（caret 入格，§5.1）。注：v1 不支持无首导管的 GFM 表格（首行无行首 `|`，如 `a | b`，合法 GFM）：cellCharRange 把首段当左缘，列映射错位一格、静默落错格（已知限制，极罕见语法，v1 不做补偿）。
