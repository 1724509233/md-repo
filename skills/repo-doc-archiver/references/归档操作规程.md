# 归档操作规程

> SKILL.md §3 流程的命令级展开。执行迁移、去重、收尾、校验时读本文。
> 批量改动铁律：**dry-run 先行 → 抽查预览 → apply → 复跑校验对比基线**。

## 0. 前置确认（一次问清，勿中途打断）

1. 仓库绝对路径 + 项目名（将用作 `1-项目/<project>/` 目录名与 `project:` 值）
2. 迁移范围（全量 / 指定目录 / 指定时间之后）
3. 是否删除仓库侧已迁文档（默认：**不删**，除非用户明确要求；删除需二次确认）
4. 归档期间 vault 同步是否需暂停（大规模迁移建议暂停，防同步回灌）

## 1. 侦察（只读）

```bash
# 文档分布（篇数 / 行数 / 最大文件）
find <repo> -name '*.md' -not -path '*/node_modules/*' -not -path '*/.git/*' \
  | xargs wc -l | sort -rn | head -40
find <repo> -name '*.md' -not -path '*/.git/*' | sed 's|<repo>/||; s|/[^/]*$||' \
  | sort | uniq -c | sort -rn

# 引用点（谁在指向这些文档）
grep -rn --include='*.md' --include='*.py' --include='*.js' --include='*.ts' \
  -E 'docs/|specs/|adr/|plans/|\.md' <repo>/AGENTS.md <repo>/RESOURCES.md 2>/dev/null

# 非 md 文档（一律不迁，只登记）
find <repo> \( -name '*.html' -o -name '*.pdf' -o -name '*.png' \) -not -path '*/.git/*'
```

vault 侧现状：`list_files(dir="1-项目/<project>")`（不存在则是全新归档）；存在则记录既有
文件清单 + 正文哈希，供 §4 去重。

**脱敏扫描（红线，不可跳过）**：

```bash
grep -rnE 'sk-[A-Za-z0-9]{10,}|api[_-]?[Kk]ey|secret|Bearer |-----BEGIN .*PRIVATE KEY|10\.[0-9]+\.[0-9]+\.[0-9]+|192\.168\.|内网|\.corp\.' \
  --include='*.md' <repo>
```

命中 → 该文件**移出迁移清单**，在报告里单列「因含敏感信息未迁」+ 建议（脱敏后重跑 / 留仓库）。

## 2. 快照与 manifest

```bash
mkdir -p $T/archiver && cd <repo>
git ls-files '*.md' | grep -v '^$' > $T/archiver/manifest.txt
git ls-files '*.md' | xargs sha256sum > $T/archiver/hashes.txt   # 迁移前后比对用
```

记录基线：vault 死链数、frontmatter 合格率、仓库测试失败集合（三者只许维持或改善）。

## 3. 整树复制（保相对链接）

**关键**：按仓库内的相对结构落到归档目录，不要在迁移时重排——`plan` 里写
`../specs/xxx.md` 这类内部相对链接会整树存活，重排则全断。

```bash
# mirror / migrate 通用：结构映射
rsync -a --include='*/' --include='*.md' --exclude='*' \
      <repo>/docs/ 1-项目/<project>/specs/    # 逐目录按 §边界判定 映射
find 1-项目/<project> -name '*.md' | xargs sha256sum > $T/archiver/vault_hashes.txt
# 与 hashes.txt 逐条比对，全等才进下一步（不一致 → 停，报告差异）
```

排除清单（默认不迁）：`node_modules`、`.git`、构建产物、lock 文件、`CHANGELOG`（工具生成）、
自动生成的 API 文档、进行中 plan、非 md 文件。

## 4. 旧副本去重三分类

对 vault 内**早于本次**的同项目副本执行。正文哈希 = 剥离 frontmatter 块 + 去行尾空白后 sha256：

| 条件 | 处置 |
|------|------|
| 正文哈希 ∈ 新权威集合 | 删旧副本（重复副本，记入修正记录） |
| 哈希不等但文件名 stem ∈ 权威 stem 集合 | 移 `4-归档/`（或项目 `legacy/`）保留异版 |
| 无 stem 对应 | **不动**——属用户手写笔记，非仓库副本 |

产出：删 X / legacy Y / 留 Z（逐条列名）。空目录顺手清理。

## 5. frontmatter 批处理

规则见 `项目模板.md §三`。要点：

- 已有 frontmatter → **跳过**（幂等，重跑安全）；`adr/` 已有 `status:` 等字段 → 合并补键不删原字段
- `title` 取首个 H1 文本；含 `:` `#` `[` `]` 或 emoji → 双引号包裹
- `tags[0]` 按目录映射表取内容类型；领域 tag 宁少不多（≤2）
- `updated` = 归档动作日；`source:` 记仓库原路径
- 完成后抽 3 份人工核对（最容易出错的是 title 抽取撞上空 H1 或代码块里的 `#`）

脚本放临时目录（**不入仓库、不入 vault**）。

## 6. 双侧收尾

**仓库侧**：

1. `AGENTS.md` 追加「文档归档」节（模板见 `项目模板.md §五`）+「留仓清单」
2. 改写路径引用：`RESOURCES.md`、代码 docstring / 注释里的文档路径 → vault 路径
   （逐处 grep 复核，别只改一处；docstring 是重灾区）
3. 用户明确要求删仓库副本时：`git rm` 逐条核对迁移清单，**确认不含留仓文件**再执行

**vault 侧**：

1. 写/更新 `1-项目/<project>/MOC.md`（骨架见 `项目模板.md §四`，含权威侧表格 + 留仓清单）
2. mirror 目录追加进 vault `AGENTS.md` 的"勿手改"清单（写明"改仓库再重跑"）
3. 项目名登记进 vault `TAGS.md` 项目词表

## 7. 校验（对照基线）

| 项 | 手段 | 通过条件 |
|----|------|----------|
| 完整性 | `hashes.txt` vs `vault_hashes.txt` 比对 | 迁移清单内全等、无遗漏 |
| 死链 | `deadlinks.py <vault>` | ≤ 动手前基线（新增即回滚修复） |
| frontmatter | `validate_frontmatter.py <vault>` | ≥ 动手前合格率 |
| 仓库回归 | 项目测试（如 `pytest -q`） | 失败**集合**不变（改了 docstring 也要跑） |

## 8. 增量重跑（第二次以后）

1. 仓库侧新文档 → 按 §3 映射补迁（新文件命名沿用模板）
2. mirror 目录 → 直接以仓库为准覆盖；vault 侧若有手改先 diff 并报告（防覆盖丢改动）
3. migrate 目录 → **不覆盖**（vault 已是权威）；仓库若仍有同名改动 → 报告冲突等用户裁决
4. 更新 `MOC.md` 索引与 `updated` 字段
5. 复跑 §7 校验

## 9. 常见坑

| 坑 | 后果 | 规避 |
|----|------|------|
| 迁移时顺手重排目录 | plan↔spec 相对链接全断 | 整树同构复制，结构映射只做顶层一次 |
| 只改 `AGENTS.md` 不改 docstring | 下次 agent 仍读旧路径 | 收尾用 grep 复核零命中 |
| mirror 目录在 vault 侧手改 | 下次重跑被静默覆盖 | 收尾登记"勿手改"；重跑前先 diff |
| 删仓库副本误伤进行中 plan | 丢活动上下文 | `git rm` 前逐条核对留仓清单 |
| 敏感文档已入 vault 才发现 | 随 LAN 同步扩散 | §1 脱敏扫描前置；发现即报告并走修正记录删除 |
| 用文件名而非正文哈希去重 | 同内容不同名 → 留双份 | stem 判定第二层兜底 |
