# 项目模板细则

> SKILL.md §1 目录契约的展开。判定"某份文档该进哪个目录"、需要 MOC 骨架时读本文。

## 一、八类目录准入判定

按"文档回答什么问题"判定，而非按仓库原目录名照搬。自上而下第一个命中的规则生效：

| 目录 | 回答的问题 | 反例（不该放这里） |
|------|-----------|-------------------|
| `specs/` | 系统**应该**是什么样（定稿的接口、数据结构、状态机） | 讨论中的备选方案 → `research/`；带勾选任务 → `plans/` |
| `plans/` | **怎么一步步做**（任务拆解、验收标准、进度勾选） | 已完成且无过程价值的碎记录 → 不迁 |
| `adr/` | 为什么**选 A 不选 B**（决策 + 被否方案 + 代价） | 实现细节、代码说明 → `specs/` |
| `issues/` | 为什么**坏了**（现象→根因→修复→预防） | 未定位的待办 → 仓库 issue tracker |
| `research/` | 外部世界**有什么**（竞品、论文、第三方能力） | 自己的结论沉淀 → vault `3-资源/` |
| `benchmarks/` | 实测**是多少**（数据、环境、结论、可复现步骤） | 无数据的性能感想 → 不迁 |
| `retrospectives/` | 这段过程**发生了什么**（时间线、决策点、行为模式） | 单纯故障根因 → `issues/` |
| `notes/` | 以上都不属（主题型知识、配置说明、临时分析） | 已能归入七类 → 别堆 `notes/` |

**`notes/` 是兜底不是垃圾场**：单目录超过 ~15 篇时按主题再分子目录（如 `notes/p3/`、
`notes/issues/`），子目录名沿用上述八类语义或项目专有主题。

## 二、命名规范

| 目录 | 规范 | 示例 |
|------|------|------|
| `specs/` `plans/` | `YYYY-MM-DD-主题.md`（保留原日期前缀，便于时间演进排序） | `2026-09-27-md-sync-design.md` |
| `adr/` | `NNNN-短横线决策名.md`（四位递增，全局不复用） | `0003-tag-pivot-drift.md` |
| `issues/` `retrospectives/` | 语义名（kebab 或中文皆可，与项目既有风格一致） | `agent-write-file-tree-stale.md` |
| `benchmarks/` | `YYYY-MM-DD-主题.md`，数据文件留仓库 | `2026-10-16-dir-scan-benchmark.md` |
| `research/` | 主题名；原始材料 → `research/sources/<来源>/` 一篇一文件 | `sources/anthropic/skill-creator.md` |
| 通用 | 不含空格；同名 basename 跨目录出现时用路径限定链接 | `[[1-项目/x/specs/a]]` |

**存量文件不改名**——改名 = 制造死链。仅新迁入文件按上表命名（原本有日期前缀的一律保留）。

## 三、frontmatter 块

```yaml
---
title: <首个 H1 文本（去 #）；含 : # [ ] 或 emoji 时加双引号>
tags: [<内容类型>, <领域1>?, <领域2>?]   # 恰好 1 个内容类型，领域 0–2 个
created: YYYY-MM-DD
updated: YYYY-MM-DD                        # 归档动作发生日
project: <项目名>                          # 与 1-项目/ 目录名一致
status: 活跃 | 已完成 | 已废弃              # 仅 plans/ 类
source: <仓库内原路径>                      # 迁移前路径，保证据链
author: repo | human | agent               # 可选
---
```

`tags[0]` 与目录的对应：`specs/`→设计文档 · `plans/`→计划 · `adr/`→设计文档 ·
`issues/`→故障排查 · `research/`→调研 · `benchmarks/`→记录 · `retrospectives/`→复盘 ·
`notes/`→知识笔记。领域 tag 取自 vault `TAGS.md` 词表；**项目名不进 tags**（走 `project:` 字段）。

`adr/` 常已有 `status:` / `date:` 等原字段 → 合并补键，不删原字段。

## 四、MOC.md 骨架（复制后填空）

```markdown
---
title: "MOC: <project>"
tags: [MOC]
created: YYYY-MM-DD
updated: YYYY-MM-DD
project: <project>
---
# MOC: <project>

<一句话：这个项目在做什么。>

## 权威侧声明（勿删本节）

| 目录 | 模式 | 权威侧 | 说明 |
|------|------|--------|------|
| `specs/` | mirror | 仓库 | 仍在演进，仓库改动后重跑归档 |
| `plans/` | migrate | vault | 已完成，仓库只留指针 |

> **改 mirror 目录请回仓库改再重跑归档**；vault 侧手改会被下次归档回灌覆盖。

## 索引

### specs
- [[1-项目/<project>/specs/xxx]] — 一行摘要

## 留仓清单（故意不在 vault）

| 文档 | 仓库路径 | 原因 |
|------|----------|------|
| README | `<repo>/README.md` | 与代码同生命周期 |
| 进行中的 plan | `<repo>/docs/plans/…` | 需随实现勾选进度 |

## 检索提示（给 agent）

改架构前先 `search_docs("<主题> design")`；已知文件用 `read_doc("1-项目/<project>/specs/…")`。
```

MOC 是**唯一手维护**的文件——其余文档的索引由它承载，不进 MOC 的文档等于不存在。

## 五、仓库侧收尾模板

仓库 `AGENTS.md` 追加节（照抄后填路径）：

```markdown
## 文档归档

本项目文档主体归档在 md-vault `1-项目/<project>/`（结构与权威侧见其 `MOC.md`）。
仓库只保留：README、CHANGELOG、进行中的 plan、<其他>。

- 查历史设计：md-vault MCP `search_docs("<关键词>")`
- 读全文：`read_doc("1-项目/<project>/specs/<文件>")`
```
