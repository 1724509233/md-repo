# 代码项目文档归档

> 仓库是文档的**出生地**，vault 是文档的**归宿地**。归档不是搬运，而是建立"仓库 ↔ vault"
> 单一权威、双向可追溯的镜像关系。

配套细则（按需加载，勿一次读完）：

- 模板细则与目录准入判定 → [references/项目模板.md](references/项目模板.md)
- 命令级操作规程与校验 → [references/归档操作规程.md](references/归档操作规程.md)

## 0. 两条不变量（先于流程）

1. **单一权威（SSOT）**：每份文档归档时必须指定唯一权威侧（仓库 or vault），另一侧只读。
   权威侧未指定就不开工——两边都能改 = 漂移必然发生。
2. **归档不删知识**：判定为"不迁"的文档也要在 `MOC.md` 留一行指针条目。vault 里可以不存正文，
   但必须能找到"它在哪、为什么没进来"。

## 1. 项目模板（目录结构契约）

归档目标恒为 `1-项目/<project>/`，`<project>` 即 frontmatter `project:` 值，
**须先登记进 vault 的 `TAGS.md` 项目词表**。固定八类 + 可选扩展：

```
1-项目/<project>/
├── MOC.md            # 唯一手维护入口：项目地图 + 权威侧声明 + 留仓清单
├── specs/            # 设计规格（已定稿的"怎么做"，方案期产物的固化态）
├── plans/            # 实施计划（带任务清单与勾选状态的过程文档）
├── adr/              # 架构决策记录（NNNN-决策名.md，只记决策与取舍，不记实现）
├── issues/           # 故障/缺陷排查记录（现象→根因→修复，可复用的避坑素材）
├── research/         # 调研、竞品、外部资料（原始材料进 sources/）
├── benchmarks/       # 基准测试与实验记录（含数据、环境、结论，可复现）
├── retrospectives/   # 复盘（时间线 + 决策点 + 行为模式提炼）
└── notes/            # 以上七类都装不下的主题笔记（可按需再分主题子目录）

可选扩展（须在 MOC 登记后才能建）：
├── reviews/          # 评审清单            ├── prompt/         # 项目内置提示词/Agent 配置
├── learning-records/ # 学习记录            ├── brainstorm/     # 头脑风暴原始记录
└── assets/           # 图示（默认不建，非 md 一律留仓库）
```

**模板是新增项目的默认值，不是对存量项目的整改要求。** 老项目只做增量补齐（缺哪类补哪类、
补 `MOC.md`），不重排、不改名——目录迁移的链接代价远高于结构美观的收益。

各目录的准入判定、文件命名示例、`MOC.md` 骨架见 [references/项目模板.md](references/项目模板.md)。

## 2. 选模式（每个一级目录各选一次）

| 模式 | 权威侧 | 适用 | 增量重跑方向 | vault 侧可手改 |
|------|--------|------|--------------|----------------|
| **mirror 镜像** | 仓库 | 文档仍在演进（活跃 spec / prompt 配置） | 仓库 → vault 覆盖 | ❌ 禁止（会被回灌） |
| **migrate 迁移** | vault | 已完成、只回溯查（历史 plan / 复盘 / 旧调研） | 无（仓库只留指针） | ✅ 可改 |

判定口诀：**"下次还要不要边写代码边改它"**——要就 mirror，不要就 migrate。
模式在 `MOC.md` 的权威侧表格里逐目录声明，不靠记忆。

## 3. 流程（六步，人在回路点已标注）

**1️⃣ 侦察**（只读，不动文件）
统计仓库文档分布（`docs/ doc/ adr/ rfcs/ specs/ plans/ issues/ notes/ *.md` + README/CHANGELOG）、
篇数与行数；找出所有引用点（`AGENTS.md`、`RESOURCES.md`、代码 docstring/注释里的路径、md 间相对链接）；
确认 vault 内是否已有该项目目录及旧副本。**产出侦察事实清单。**

**2️⃣ 边界判定**（用 §4 决策表逐目录过一遍）
→ 🚪 **人工确认点 A**：把"迁 / 留 / 删（重复副本）"三分类清单给用户拍板。这一步不确认，
后面全是返工。

**3️⃣ 建模板**
按 §1 建 `1-项目/<project>/` 骨架（只建实际有内容的目录，空目录不建）；
`<project>` 先登记进 `TAGS.md` 项目词表。

**4️⃣ 迁移**（幂等，详见操作规程）
脱敏扫描 → 整树按**相对结构**复制（保内部相对链接存活）→ 逐文件 sha256 校验 →
补写 frontmatter（已有则跳过，幂等）→ 旧副本按"去重三分类"处置。

**5️⃣ 双侧收尾**
- 仓库侧三件事：**指针**（`AGENTS.md` 加"文档归档"节，写明归档位置 + 用 `search_docs` 检索的示例）、
  **路径引用改写**（README/RESOURCES/docstring → vault 路径）、**留仓清单**（声明哪些文档故意留在仓库）。
- vault 侧两件事：写/更新 `MOC.md`（含权威侧表格）；mirror 目录追加进 vault `AGENTS.md`
  的"勿手改"清单。

**6️⃣ 校验**
死链扫描 + frontmatter 校验（对比基线，只许减少）+ 仓库测试基线回归（失败集合不得变化）
→ 🚪 **人工确认点 B**：报告 X 迁 / Y 留 / Z 删 / W 改引用，逐条列名。

## 4. 进 vault / 留仓库 决策表

| 文档类型 | 去向 | 归档目录 | 理由 |
|----------|------|----------|------|
| 设计 spec / 方案 | vault | `specs/` | 高回溯价值、低修改频率 |
| 实施计划（已完成） | vault | `plans/` | 过程证据，不再编辑 |
| **实施计划（进行中）** | **仓库** | — | 需与代码同步勾选，改一次回灌一次 |
| ADR | vault | `adr/` | 只增不改，天然适合归档 |
| 故障/缺陷排查记录 | vault | `issues/` | 避坑知识库，跨会话召回价值高 |
| 调研 / 外部资料 | vault | `research/`（原文进 `sources/`） | 证据链需长期留存 |
| 基准测试 / 实验记录 | vault | `benchmarks/` | 数据+结论，决策依据 |
| 复盘 | vault | `retrospectives/` | 行为模式提炼，长期复用 |
| 项目内置 prompt / agent 配置 | 视活跃度 | `prompt/`（mirror）或仓库 | 与运行时强耦合 |
| **与代码同生命周期的接口/使用文档** | **仓库** | — | README、API 文档、CHANGELOG、脚手架模板 |
| **非 md 文件**（HTML/PDF/图片/二进制） | **仓库** | — | vault 只处理 md；需要时在 MOC 登记仓库路径 |
| 敏感内容（key/token/内网地址/客户数据） | **两侧都不** | — | 见 §5 红线 |

## 5. 红线（无例外）

- **密钥永不入 vault**：归档前必须跑 secret 扫描（`sk-`/`api_key`/`token`/`Bearer`/私钥块/内网 IP 与域名）。
  命中即从迁移清单剔除并向用户报告——vault 会经局域网同步扩散。
- **非 md 不迁**：只在 MOC 留仓库路径指针。
- **mirror 目录禁手改**：改仓库再重跑；已在 vault 侧误改的，与仓库正本 diff 后记入 `4-归档/修正记录-*.md`。
- **不主动重排存量目录**：模板只做增量补齐。
- **`MOC.md` 与实际不符 → 直接修**（属链接维护，无需请示）。

## 6. 完成判定（Definition of Done）

- [ ] `1-项目/<project>/MOC.md` 存在，含权威侧表格 + 留仓清单 + 全量文档索引
- [ ] 所有归档文档 frontmatter 合规（`title` / `tags[0]`∈内容类型词表 / `created` / `updated` / `project:`）
- [ ] `<project>` 已登记进 `TAGS.md` 项目词表
- [ ] 迁移文件与仓库正本哈希一致，无遗漏（对照 manifest 逐条核对）
- [ ] 仓库 `AGENTS.md` 有"文档归档"指针节；代码内文档路径引用已指向 vault
- [ ] 死链数、frontmatter 合格率均不劣于动手前基线；仓库测试失败集合无新增
- [ ] 三分类报告（迁 / 留 / 删）已交用户确认
