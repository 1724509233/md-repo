Design-first 四项

  • 放置左 = 展示层（品牌 32px + 标题/文档/状态两行，flex-1 只读）；右 = 操作层（shrink-0：新会话 → 自动批准 → 关闭）。层级：标题 14/600 > 状态 12 > 路径 11（最弱、可省略）> icon 按钮（ghost）。自动批准 icon 按钮的 ON 态是头部唯一颜色载体——安全状态 ON 时整块 brass，扫一眼可读
  • 过渡自动批准 ON/OFF：图标色 + 18% 底色 + 45% 边框三通道 150ms 变色，无 reflow 无位移；三个 icon 按钮 hover = brass 10% 底色、active = scale(.95)（沿用 confirm 按钮语言）；抽屉自身 right/bottom 过渡不动（tests/test_ui.py 钉住，实现时保留）
  • Reflow唯一可压缩元素 = 文档路径（ellipsis + min-width:0，窄窗先省略）；标题/状态行右组定宽。状态行恒单行不换行（「就绪/思考中」均为短词）；标题定宽 51px 不参与压缩
  • Toggle 两态30px icon 按钮两态只由颜色区分：OFF = ghost/ink-soft，ON = brass 图标 + 18% 底色 + 45% 边框（inset 阴影），几何零变化 → 位置不跳；role=switch + aria-checked + title tooltip 恒在，原生 button 键盘可达

死胶囊「当前文档」· 两种形态

已拍板 A降为只读上下文指示：标题行上 11px 路径（mono，file 图标，hover 看全路径，无点击无 hover 变色），未打开文档时整块隐藏。

  • 理 1agent 每条消息都带 doc_path，「对话基于哪篇文档」是用户判断所需的状态信息，不是实现 meta
  • 理 2移动 80vh 抽屉下 TopBar 被 backdrop 遮住，头部是移动端唯一能看到当前文档的位置；桌面则与 TopBar 互补（会话上下文 vs 应用上下文）
  • 理 3零维护成本：无状态无事件，v-if 一个 prop；替代掉「可点的装饰」，不让交互诚实性倒退

形态 B 整体移除（仅供对比）：头部最干净，桌面端 TopBar 已有当前文档。上方操作台可切换 B 查看对比效果；拍板为 A。
