A 索引

立场：改动最小、最贴近现有纸墨风。48px 细 rail 只做导航，搜索升级为「按文件分组的富卡片」。树内搜索框移除，搜索统一收进搜索页。

token 取用

全部复用 --paper --ink --ink-soft --brass --line --surface，零新增颜色。rail 与面板同 --paper 底，靠 1px --line 分隔；面板头用 --surface 提一档。

rail 宽度与间距

  • 宽 48px（按钮 36×36，圆角 9，图标 19px，stroke 1.6）
  • 垂直节奏：上 padding 10px → logo 28px → 14px 间隙 → 图标组 gap 6px → 分隔线 → 预留位
  • logo：28px 方形「M」mark（复用 .logo-mark 缩小），只留 mark 不放字，宽度放不下

active 态策略（三态）

inactive
hover
active

active = 实心黄铜底 + paper 图标（与「保存」按钮同权重语言，全 rail 唯一高亮）；hover = ink 5%；inactive = --ink-soft。预留位：虚线框 + 55% 透明度 + 不可点。

文件页 · 树内搜索 & 收起全部

  • 树内搜索框：移除。理由：它正是「信息不足」问题的来源（260px 下拉只能塞一行小字）；去掉后文件页回归纯文件管理，且树不再因「搜索打开时隐藏」而闪烁（现状 v-show="!searchOpen" 会整棵隐藏）。
  • ① 收起全部 放在面板头右侧（mockup 中标注 ①）：结构化工具栏位，与「文档」标题同行，常驻可见；未来「展开全部 / 过滤」加在旁边即可，不会溢出。
  • 树本体：行高、chevron、count pill、active 黄铜态、拖拽全部保留不动。

搜索卡片字段取舍

  • 按文件分组（同一文件的 segment 收进一张卡片，skill.md 演示 2 段）：vault 里「文档」才是单元，平铺会让同一文件名重复 6 次。
  • 保留：文件名 / 完整路径（mono 10.5px 截断）/ heading 路径（黄铜点引导）/ content 片段（12px，3 行 clamp，匹配词黄铜高亮）/ score（mono 数字 pill，取该文件最高 segment 分）。
  • 去掉：kind（段类型）、segment 级 score（组内无区分度，噪声）。
  • 「展示更多」沿用现有 .search-more 胶囊按钮规格（预取式交互不变，文案改为「N 个文档 · M 段更多」）。

页面切换 & 状态保持

  • 过渡：180ms slide+fade（translateX 10px → 0，ease-out，GPU，无 reflow）。选 slide 的理由：rail 图标 = 「翻页」心智，方向感有助于确认切到哪页。
  • 实现：两面板常驻 DOM（v-show），切页时给新面板加 anim class；搜索词、结果、滚动位置、树展开态全部保留（状态在组件 ref 里，v-show 不销毁）。
  • prefers-reduced-motion：退化为无动画直切。

移动端（<1024px）

桌面：rail + 面板
移动：rail 隐藏，整栏滑出（现状）
  • 保留现状整栏 drawer（hamburger 唤出 260px 全宽面板 + overlay），不在手机上放 rail：48px 占屏 ~13%，无增益。
  • drawer 顶部加一个「文件 | 搜索」分段切换，搜索页在 drawer 内渲染同样的富卡片（竖屏全宽，卡片反而更舒展）。

B 书房

立场：左侧是「正经导航区」，对新手自解释（rail 带 11px 中文标签）；搜索是第一公民——面板放宽到 300px，结果平铺、视觉化（相关性条），不堆数字；树内保留轻量搜索作快速跳转，双轨并行。

token 取用

同 A，零新增颜色。差异在分层：rail 用 --surface（比 --paper 亮一档）自成一层，文件页保持 paper 底；搜索页面板整体 --surface 底，卡片仍是 surface + 1px --line，靠 border 分离。

rail 宽度与间距

  • 宽 64px：按钮 52×44，图标 20px（stroke 1.5）+ 下方 10px 标签，gap 4px，垂直 padding 12px
  • logo 不在 rail：移到主区 TopBar（mark + wordmark，mockup 顶栏可见）。理由：64px 要装图标+文字，再塞 logo 会挤；wordmark 属于品牌识别、不属于导航。
  • 底部预留「设置」位（margin-top:auto 贴底），与上方导航组用分隔线区隔。

active 态策略（三态）

inactive
hover
active

active = 黄铜 10% 底 + 黄铜图标 + 左缘 3px 黄铜条（条宽 3px、上下 9px 圆角）。选「条」而非实心：带标签的 rail 本身信息量大，实心块会让 64px 看起来太重；条与正文区 #preview h1 的黄铜下划线呼应。

文件页 · 树内搜索 & 收起全部

  • 树内搜索框：保留（现状原位，树顶）。理由：快速跳转场景留在手边（树旁边 1 次点击可达），下拉行可以保持现在的名 + heading 两行（它负责「找到文件」）；深阅读交给搜索页（负责「看到内容」）。双轨分工，互不重复。
  • ① 收起全部 同样放在面板头右侧（mockup 标注 ①）——与 A 相同位置，但头部只承担标题 + 一个动作，更安静。

搜索卡片字段取舍

  • 平铺不分组：每个 segment 独立成卡（skill 的两段是两张相邻卡片）。理由：命中即单元，用户扫的是「哪段命中」，不是「哪个文件命中」；文件名片可重复。
  • 保留：文件名 / 路径（同行，mono 10px 截断）/ heading（做成 pill chip）/ content 片段（12px 3 行 clamp，高亮）。
  • score 呈现：不用数字，用卡底 3px 黄铜相关性条（宽度 ∝ score，最高分 = 100%）。理由：数字（0.91 vs 0.88）无绝对意义，条只表达相对强弱，且是纯视觉、零认知负担。kind 同样去掉。
  • 输入框下方加一行 meta：「N 个片段 · 当前档 strict · 不足时自动补档」，把分层召回机制显性化（现有机制只在 agent 端可见）。

页面切换 & 状态保持

  • 过渡：200ms 纯 fade，无位移。理由：64px 带标签 rail 的切换更像「翻标签页」，纯淡入最安静；slide 在宽 rail 上会显得面板在「挤」。
  • 两面板常驻（v-show），搜索词 / 滚动 / 树展开全部保留。搜索面板宽度不同（300 vs 250），切换时主区内容会重新排——接受，因为搜索是主动行为。
  • prefers-reduced-motion：直切。

移动端（<1024px）

文件页：48px rail（去标签）+ 面板
搜索页：80vh 底部抽屉（同 AI 抽屉）
  • 文件浏览保留 48px rail（去文字标签，只留图标）+ 面板常驻：rail 在竖屏是省空间的二级导航（260px 全宽面板 + 48px = 只吃掉 ~12%）。
  • 搜索页改用 80vh 底部抽屉（完全复用现有 #ai-panel 移动抽屉的 CSS：圆角 24、backdrop、拖拽手柄）：竖屏下卡片是「内容」，全屏阅读比侧栏更合理；rail 的搜索图标 = 抽屉的 toggle。代价：比 A 多一套抽屉状态，实现量略高。

C 档案

立场：最「有个性」。56px 墨色深色 rail 给暖纸界面一个沉稳锚点（唯一深色变体）；检索结果像翻开档案——无卡片、无高亮、衬线正文，克制阅读；把全局「收起全部」收在面板底部，头部彻底清空。

token 取用

仍零新增颜色：深色 rail 直接用 --ink 作底色，图标/文字用 --paper 的 color-mix 降透明度（55% / 14% / 30%），active 指示点保留 --brass。墨色是主文字色，不是新色，视觉风险可控；若顾虑对比，rail 可退回 --surface，其余不变。

rail 宽度与间距

  • 宽 56px（介于 A 的 48 与 B 的 64 之间）：按钮 38×38，圆角 9，图标 19px；垂直 padding 12px，图标组 gap 6px
  • logo 回 rail 顶部：28px 黄铜「M」mark（深色底上更醒目），不放文字——品牌位与导航位同栏，左侧视觉重心完整。
  • 无文字标签（深色窄栏 + 标签会显杂），靠 tooltip + 面板头标题（文档/检索）解释当前页。

active 态策略（三态）

inactive
hover
active

active = paper 14% 底 + 右上角 5px 黄铜点（点 = 「你在这里」的书签记号，档案语境）；hover = paper 10%；inactive = paper 55% 透明。深色栏上不用实心黄铜块，避免与保存按钮抢焦点。

文件页 · 树内搜索 & 收起全部

  • 树内搜索框：移除。理由：C 把「检索」当作目的地（rail 一级入口），文件页只承担浏览；且深色 rail 已经把注意力引向搜索页。快速跳转的损失由搜索页的即时结果（300ms 防抖 + 预取）弥补。
  • ① 收起全部 放在面板底部常驻 footer（mockup 标注 ①）：11px 文字按钮「收起全部文件夹」+ 预留「展开全部」。理由：这是低频操作，头部两个变体都把它放在最显眼的地方是过度暴露；底部 footer 顺手但不抢戏。另在每个目录行 hover 时出现「收起本目录」按钮（mockup 树行右缘可见），两级控制互补。

搜索卡片字段取舍

  • 档案式开栏，无卡片：透明底 + 块间 1px 分隔线，文件名用衬线 15px（书名感），文件名行下缘一条黄铜细线（呼应 #preview h1 的标题线）。
  • 不高亮匹配词：snippet 用衬线 12.5px 原文呈现。理由：档案语境的阅读优先于定位；高亮会让 260px 宽的衬线文本碎片化。定位交给 heading chip + 点击后正文里的 heading-flash 标记（现有能力）。
  • 保留：文件名 / 路径（mono 10px，文件名行右侧基线对齐）/ heading（mono 小字，行首）/ content 片段（3 行 clamp）。同文件多段：文件名行只出现一次，段间虚线分隔（skill 演示 2 段）。
  • score：完全不显示（档案不标价）；排序即相关性，「展示更多」按钮保留（沿用现有胶囊规格）。输入框做成下划线式（无圆角无边框底色），与整体编辑气质一致。

页面切换 & 状态保持

  • 过渡：160ms 纯 fade，三变体中最短。理由：档案切换应像「换开栏」，快而静；深色 rail 的 active 点已经给出位置反馈，不需要面板再动。
  • 两面板常驻（v-show）：搜索词、结果、滚动、树展开全部保留，切走再回来原样。
  • prefers-reduced-motion：直切。

移动端（<1024px）

文件页：48px 深色 rail + 全高面板
搜索页：48px 深色 rail + 面板（同栏切换）
  • 保留 48px 深色 rail + 面板，两个页面都在常驻栏内切换（不做抽屉、不做整栏滑出）。理由：深色 rail 在移动端是一条「书架侧板」，视觉成立且成本最低——直接复用桌面布局，零额外状态机。代价：竖屏下主区被 48+260 压缩，需在小屏断点把面板收到 232px。

推荐与取舍

推荐：变体 A（索引）。理由：它把本次重构的目标（搜索信息不足）解决得最直接——分组富卡片 + score + 高亮，且改动面最小（48px rail + 两个页面 + 移除树内搜索），移动端沿用现状 drawer，实现风险最低；实心黄铜 active 与现有「保存」按钮、heading-flash 等黄铜语言完全同族，不需要新的视觉词汇。

B 的价值在「搜索是第一公民」的宽面板与相关性条，适合你更看重搜索体验而非最小改动时选；代价是移动端多一套 80vh 抽屉状态。C 气质最足（墨色 rail + 档案开栏），但深色栏与现有暖纸体系的冲突、以及「不高亮 + 不显示 score」会削弱本次重构「让信息被看见」的初衷，适合作为长期品牌探索而非首版。

三个变体的共同底线：token 零新增、两面板常驻 v-show 保状态、prefers-reduced-motion 降级、rail 预留位（最近变更 / 通知）一律虚线不可点。
