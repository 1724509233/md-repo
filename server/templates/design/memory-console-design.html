布局决策 · 300px 左面板
  • 位置——控制台与文件/搜索面板同位、同宽（300px，沿用 .console 宽度类），是 rail 的第五个实槽位。审查是「主动发起、低频长留」的扫描动作，与搜索同性质；放左侧不挤编辑器，且可独立于主区开合。
  • 过渡——开合只用 opacity + transform（.c-face.anim 8px 位移入场，面切换同理）；主内容区不参与 flex 变化，零回流，文字不重排、滚动位置不受影响。关闭态 .console.closed 宽 0 + pointer-events:none，不占位、不可点。
  • 触发——rail「通知」槽位（当前为虚线占位，app.js:273）激活为实槽位；徽标数 = awaiting_review 队列长度，红铜徽标与 .spill.awaiting 脉冲同色系，一眼可辨「需要我」。其余预留槽位（最近/设置）保持虚线。
  • 队列卡片——一行一提案：类型 chip + 标题 + 年龄；次行 mono 给来源路径 + run_id 批次号（对齐 /api/memory/status.awaiting_review 字段）。脉冲只给最新到达的一条，避免多卡同时闪烁的噪音；选中卡 .q-card.sel 高亮，点入场景 02。
  • 脉搏——by_status 恒定 9 格（API 保证稳定形状，含非零 merged=5，证明执行器真的在落地）；trigger 行 = 触发计数（满足条数 / 所需条数，每次 run 后清零）+ 今日 run 预算；召回块 = 7d 无命中 / 在轨文档 / top 加权。整块只读，就是「30 秒扫描」的目标。

信息架构 · 为什么是这个顺序
  • 判断优先——顶部 = 类型 + 状态 + 标题 + 年龄（半秒知道「什么类型、等什么」），紧接着内容摘录（一秒知道「对不对」）。人不需要先看到批次号才能判断。
  • 信任凭据——来源 source_refs 渲染为可点击路径（跳到原文），相似记忆比对回答「会不会和已有记忆重复/冲突」——这是 sentinel 的职责核心（召回源触发）。两段共同构成「信不信」的证据。
  • 兜底信息——run_id 关联 agent 批次、可逆性 pill 说明「反悔可回滚」。它们影响判断下限（敢不敢一键过），所以排在证据之后。
  • 动作行 sticky——adopt 红铜实心 = 主操作（预期多数提案会被采纳）；reject 描边次要，点击展开必填理由 textarea，提交按钮在输入非空前保持禁用——服务端同样 400 强校验（reason required，信任升级数据源，spec §7.1）。
  • 确认之后——状态翻 adopted / merged + merged_at 时间戳；「执行器已落地」给出实际变更的文件路径，并附 change_log 轨迹（seq + actor：human → executor）让闭环可见。executor 行在真正落地前保持虚线 +「下一循环」标注（API 只移状态，执行器才落文件——spec 铁律）。

空态与稳态处理
  • 空态是最高频状态——队列清空后不隐藏面板、不给「无数据」死路：轻环图标 + 一句结论「无待审提案」+ 副文案「系统运行正常，脉搏见下」+ 历史行「上次终审 2 条 · 今天」，传达「系统活着，只是没事」。
  • 脉搏常驻——awaiting_review 归零、merged 累积递增（5 → 6），trigger 与召回块原样保留：即使没东西要审，也能确认 agent 与执行器仍在运转。rail 徽标随队列归 0 消失，红铜脉冲随之熄灭。
  • 演示脚本——场景切换 tab + 场景 02 的采纳/驳回交互，均为本页最小 <script>，只操作 class 与文本，不调真实 API；生产接线 = 按钮 → /api/memory/proposals/{relpath}/adopt|reject，成功则切到确认之后子视图，400（状态已被别人改掉）则提示并重新轮询。
