frontmatter 元数据卡片 · 设计对比稿

三个变体共用同一套「纸墨书房」token 与 grid-rows 折叠机制，差异只在信息组织方式与折叠后露出的内容。每个变体含三个实例：A 报告（14 key）展开 / A 折叠 / B 笔记（3 key）展开，均按真实预览列宽 680px 渲染（下方淡色文字为正文占位）。点卡片头部可试折叠。

注记中「展开态」= 打开全部字段；「折叠后」= 收起后头部露出的摘要。

VARIANT 01

索引条 · 字段网格

推荐

字段自动折行的松散标签格（2–4 列），最松弛；折叠后头部给出一行 mono 摘要 alias · status · 时间，不带状态点。

Relay 实验记录

正文占位 —— 3 个 key 一行排开，不占正文空间感。

设计注记

  • 配色：surface 卡片 + line 描边；唯一强调是 brass 图标 / chevron；label ink-soft，value 深 ink，零新增颜色。
  • 字号 / 间距：key 10px Inter 大写 + 0.07em 字距，value 12.5px JetBrains Mono 等宽数字（tabular-nums）；网格 auto-fill 152px，14 key ≈ 4 列 × 4 行。
  • label/value 对比：label 小、淡、大字距；value 大、实、等宽 —— 靠尺度与色彩浓淡拉开，不加竖线。
  • 默认态：≤ 6 key 默认展开；> 6 key 默认折叠（报告首屏先看摘要行，不看字段墙）。
  • 折叠后：一行 mono 摘要 alias · status · 开始时间 · rounds（11.5px ink-soft，单行省略）；「N 项」徽标让位给摘要。
  • chevron：头部右侧，展开时旋转 90°（与文件树 .chev 同向）。
  • 取舍：无分隔线最松弛，但长值换行会轻微打破行间对齐；信息密度低于规格表。

Relay 实验记录

正文占位 —— 3 行账本，稀疏但整齐。

设计注记

  • 配色：surface 底 + brass 6% 头底色 + line 55% hairline 行分隔 —— 三者中最「账本 / 文档」。
  • 字号 / 间距：两列 140px / 1fr（最宽 key tokens_completion 不截断），label 11px Inter 大写 ink-soft，value 12.5px Mono ink；行高 1.9，行间 hairline，行 hover ink 3%。
  • label/value 对比：同一行内「淡小 vs 深实」，key 名同列垂直对齐，14 key 扫读最省力。
  • 默认态：≤ 6 key 默认展开；> 6 key 默认折叠（单列账本展开 ≈ 400px 高，不宜首屏占满）。
  • 折叠后：头部露 状态点 + alias · 起止时间 · rounds；点色直接复用 .status-dot（ok 绿 / error 红 / round_limit 橙 / timeout 深橙 / empty 灰），运行异常折叠后也一眼可见。
  • chevron：头部右侧，展开旋转 90°；头部整行可点。
  • 取舍：可读性最高、占高最大；长值单行不折列，列宽内 break-word。

Relay 实验记录

正文占位 —— 笔记场景深色块偏重，是否通用需权衡。

设计注记

  • 配色：底 ink、文字 paper 反白，brass 仅给标题 / key / 图标 —— 呼应 mode-btn active 与 logo-mark，零新增 token。
  • 字号 / 间距：key 10px Inter 大写（brass 65%），value 12.5px Mono paper 92%；网格 1px gap + paper 11% 底色勾出 hairline 网格。
  • label/value 对比：暗底上靠「brass 淡 key vs paper 实 value」，比亮底版本对比更强、更「仪表盘」。
  • 默认态：≤ 4 key 默认展开（稀疏时整块更干净）；> 4 key 默认折叠。
  • 折叠后：状态点常驻头部（深底上 brightness 提亮 + 微光晕）+ alias + status；右上保留「N keys」计数；卡片高 ≈ 44px。
  • chevron：头部右侧，展开旋转 90°，hover 时提亮至 paper。
  • 取舍：最抢眼，但与纸墨正文反差最大；深色块建议只给报告类文档，普通笔记用会有点「重」。
